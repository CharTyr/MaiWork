# 调研报告

目标：装了 MaiWork 的每个群，拿到的调研结果都长一个样——**结论先行、每条有出处、拿不准的说清楚、
手机上一眼能看懂**。宁可少写一条，也别写一条编的。

## 一、先定要回答什么（动手搜之前）

1. 把任务原话拆成 **3~8 个要回答的问题**。原话点名要的（比如「价格」「能不能国内用」）一个都不能丢，
   原话没要的别自己加大。
2. 如果是**对比 / 盘点**（几个东西放一起比）：先定**对象清单**和**字段清单**——
   - 对象：要比的那几个（原话给了就用原话的；没给就先列候选，挑最相关的，一般不超过 8 个）；
   - 字段：每个对象都要填的几项，每项写清**类型**（数字 + 单位 / 是否 / 一句话 / 日期）和**口径**
     （比如「价格 = 个人版月付，美元」）。口径不定，后面的数字就没法比。
3. 把问题和字段写进这一步的产出目录 `outline.md`（几行就行），后面照着填，不要边搜边改题。

## 二、逐项找证据

- 用 `web_search` 找，用 `fetch_page` **打开原文**看；只看过搜索摘要的不算查到。
- **一手来源优先**：官网、官方文档、价格页、公告、论文、原始数据；媒体报道和博客是二手，
  能追到一手就追。
- **每个数字、每个结论都要带来源链接**，记下是在哪一页看到的。
- **按独立来源数算证据强度，不按链接数**：不同网站转载同一篇稿子 = 1 个来源。
  写的时候标「多源」（≥2 个独立来源）或「单源」。
- **拿不准就标出来**：某个字段查不到、来源互相打架、只有单个非官方来源——在笔记里标 `[不确定]`，
  并写一句原因。**不确定的值不进结论、不进图表**，单独列进报告的「还没确认的」。
- 来源说法不一致时，先看是不是**口径或时间点不同**（比如一个是去年价格、一个是今年），
  不同口径不自动等于矛盾；真矛盾就把两边都摆出来，不要取平均。
- 够用就停：关键问题都有可靠依据、没确认的已经标好，就别为了凑数继续搜。

中间产物（笔记、表格）写在这一步的目录里，用 `write_file`；后面的步骤会读它。

## 三、汇总成报告

报告的组织顺序（没有内容的段落直接省掉，别硬凑）：

1. **一句话结论**——直接回答原话问的问题（「推荐 A，因为…」「目前查不到 X 的官方数据」）。
2. **关键数字 / 对比**——最能支撑结论的几项数据（适合画成图的放这里）。
3. **大家都同意的**。
4. **有分歧的**——把分歧摆出来，写清各方依据。
5. **吐槽最多的 / 要小心的**——常见坑、风险、限制。
6. **新冒头的**——最近的新变化（写明时间）。
7. **还没确认的**——标了 `[不确定]` 的项和原因。
8. **来源**——所有用到的链接。

### 交付成网页（任务要的是网页、或没指定形式但内容以调研为主）

用 **`render_report`** 工具生成 `index.html`，不要自己写 HTML/CSS——程序统一排版、配色、手机适配和深浅色。
零件怎么对应上面的段落：

| 段落 | 用哪个零件 |
|---|---|
| 一句话结论 | 报告的 `caption`，或第一个 `takeaway` |
| 关键数字 | `stat` / `stats`（1~4 个大数字）；同一单位几项比大小用 `compare`；按时间变化用 `line` 或 `bars`；占比用 `share` |
| 多对象 × 多字段 | `table`（格子里写短文字或数字，不确定的格子写「未确认」） |
| 各段标题 / 正文 | `heading` + `text` / `list` |
| 时间顺序的事 | `timeline` |
| 风险、还没确认的 | `note`（每条一个，或一个 `list` 跟在 `heading` 后） |
| 来源 | 最后一个 `sources`（链接只能是 http/https） |

规矩：
- **图表里的每个数字都必须是你查到、标了来源的**；不确定的不进图表。
- 数字字段只写数字，单位写在 `unit` 里（`"value": 12.5, "unit": "亿美元"`）。
- 一个零件讲一件事；内容多就多用 `heading` 分段，别把十几行塞进一个 `list`。
- `render_report` 报「规格不合格」就照提示改了再交，不要退回手写 HTML。

### 交付成文字 / 文件

照同样的段落顺序写 Markdown（或按任务要求的格式）。每条后面跟来源链接，标「多源 / 单源」。

## 四、写给群友看

- 不写任务编号、步骤编号、文件路径、「子 agent」「主模型」这类内部说法。
- 用大白话；专业词第一次出现时用半句话解释。
- 不夸大：查到「官方说支持」就写官方说支持，没实测就别写成「实测可用」。
