# 通用任务交付标准

这份是所有派活的通用底线。更专的做法另有两份：要产办公文档看 `office-docs`，
要核实资讯看 `news-verify`；资讯收录标准在 `news-standard`。

## 什么时候读这份

- 接到一条派活、开工之前（先看清要交什么形态的东西）；
- 写完成品、要交回之前（逐条过自检清单）；
- 写交付说明之前。

## 一、先看清要交什么形态

计划里给了 `deliver_kind`，三种形态的产物落点不一样：

| 形态 | 交什么 | 产物写到哪 |
|---|---|---|
| `text` | 一段要直接发进群的**完整回复原文** | `artifacts/<任务ID>/reply.md`（只有正文，别写「以下是回复」这种壳） |
| `view` | 一个能在手机打开的单页网页 | `artifacts/<任务ID>/` 下的 HTML（图片、样式一起放进去） |
| `file` | 一个能下载的文件（表、文档、图、压缩包） | `artifacts/<任务ID>/` 下的成品文件 |

- `text` 活最容易翻车：**群友最后看到的就是 reply.md 里的原文**。只把答案写在交回总结里，
  群里只会收到一句很短的交付说明，答案等于没发出去。整段原文最多 1500 字，超了按群文件发。
- 产物一律写在 `artifacts/<任务ID>/` 下，用相对路径，不要写绝对路径。
- 群友给的原图在 `artifacts/<任务ID>/input/`：那是**材料**，不是成品；拿它当交付会被打回。

## 二、先给结论

- 交付说明 ≤60 字，**第一句就是结论**（做成了什么 / 查到了什么），不要「已完成，请查收」。
- 网页 / 文档的第一屏也要先给结论，别先铺三段背景。
- 交回总结同样先给结论，再给依据；主流程会按它写交付说明，你写清楚它才不会写歪。

## 三、不编造

- 没打开的链接不算依据，不许假装打开过；打不开就写明打不开。
- 数字、日期、口径照原文抄；算出来的要能说清算的是什么。
- 查不到就写查不到，不许用「据称」「可能」把没核实的说法写成结论。
- 不确定的点单独标出来（写 `[不确定]`），交回时列成一份「未确认」清单。
- 编一个看起来合理的答案，比交回「没查到」严重得多。

## 四、成品自检（交回前逐条过）

1. **产物真在**：用 `read_file` / `list_files` 再确认一遍路径对、文件不是 0 字节。
2. **能打开**：网页能被浏览器打开、文档能被对应程序打开、表格数据行数对得上。
3. **没有占位符**：搜一遍 TODO、待补充、此处不写、另开一次调研、示例数据——有就补完或删掉。
4. **数字对得上**：正文里每个数字都能指到来源或自己的计算过程。
5. **没有内部说法**：成品和交付说明里不出现任务号、`artifacts/` 这类路径、job 编号、
   「主模型」「子 agent」「上一步」；要引用别的东西就说清是什么（「第 1 步查到的资料」）。
6. **形态对**：`text` 活确认 reply.md 里是能直接发出去的完整原文；`view` 活用手机宽度看一眼；
   `file` 活确认文件名不含内部用语、扩展名和内容一致。
7. **覆盖了要求**：计划里每条要求都对得上一个产物或一段正文，没有漏项。

## 五、调研类的活按六段组织

调研、对比、盘点、「大家怎么看」这类活，交给群里的成果按这六段组织，别写成一堆链接：

1. 一句话结论；
2. 大家都同意的；
3. 有分歧的（把分歧摆出来，不要取平均）；
4. 吐槽最多的；
5. 新冒头的；
6. 没人提的（值得注意的空白）。

六段是**组织框架，不是扩搜配额**：按原话和手上已有的证据组织，关键问题有可靠依据、
未确认的点已说明就停，不用为了凑满每一节再去搜。

每一点都要带链接，并标明「多源」（至少 2 个独立采集或独立确认的来源）还是「单源」；
不同站点转载同一来源，不算独立佐证。说法不一致不自动等于事实矛盾——置信程度或时间点不同
是两回事。

## 六、随口一问的活别做重

计划标了 `brief`（规模档）时，那句话的意思是：**篇幅：几句话回答清楚，不做网页/文件**。
只交回几句话的结论和关键出处，不做网页、不做文档、不做长报告。

## 七、多步任务

- 有上游步骤时，先看上游交出来的资料在不在；没交出来就不要硬开工。
- 中间步骤（后面还有活要用它的结果）把产物写到 `artifacts/<任务ID>/steps/<步号>/`，
  成品才写到 `artifacts/<任务ID>/` 下。
- 复用上一轮存档前先确认它还是对的，别把过期数据当现成的。

## 八、怎么交回

- 用 `submit_result` 交回：总结 + 产物路径 + 关键依据；**不能宣布任务完成**，
  完成与否由主流程验收。
- 交回前把上面的自检清单过一遍；有做不到的，如实写在交回里，说清试过什么、卡在哪。
- 需要查群里的资料先用 `read_chat_history` / `search_memory` / `read_profile`，
  需要联网用 `web_search` / `fetch_page`；要写文件用 `write_file`。
- 不确定该用什么做法时，用 `list_skills` 看有哪些 skill，用 `read_skill` 读全文。
