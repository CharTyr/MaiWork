# 怎么找

## 定关注点

给 3–5 个分散的关注点，每个是一句能直接拿去搜的具体关键词，加一句「为什么这个群会在意」：

1. 来自「最近在聊」的最多 2 个；
2. 至少 1 个来自长期兴趣、在做的事、常用资源；
3. 1 个「拓展」方向，用「跳一步」找（见下）；它的「为什么」写成从哪条兴趣跳过来；
4. 可选 1 个「不同角度」：对群正在聊的话题的反方 / 批评 / 另一种看法，必须是观点或分析文章，不是同一话题的另一条新闻；找不到就不给。

已经饱和的话题（最近发得多的）、最近几轮已经找过的方向，除非有重大新进展，这轮别再找。

## 跳一步

从群的一个兴趣出发，往外走一步，不要停在原地：

- 同一制作人 / 工作室 / 作者的其他作品或新动向；
- 群在用的东西背后的技术、设计取舍、行业内幕；
- 同类型里没什么人注意的冷门佳作；
- 相关的数据、冷知识、历史上的今天。

例：群在聊 NS2 底座发烫 → 找底座散热设计的来龙去脉，而不是再找一条「NS2 发烫」新闻。
群里正在聊的那件事本身不算拓展。

## 找候选

1. 资讯的搜索不用填 days：程序默认只搜最近 7 天；找文章时 days 填 180，而且要能看到发布时间。
   每个关注点换几种问法（一手来源、技术细节、社区讨论、反面意见、本地语言、后续进展），别同义改写反复搜。
2. 每条都要用 fetch_page 真打开原文再看一遍；没打开过的程序一律不收。
3. 打开后先确认发布时间：看文章页头的日期、meta 里的发布时间、网址里的日期；实在找不到就把 published 留空——资讯留空还能靠打分判新旧，文章留空会被直接拒掉。
4. 从原文里抄一小段能支撑摘要的依据（quote）；摘要只写原文里有的。
5. 要登录 / 付费才能看的，标 paywall，别当正常候选。
6. 按群画像自己「跳一步」拓展出来的方向，交回时标 explore。
7. 交回的数量有上限；凑不满就少交，宁缺毋滥。
