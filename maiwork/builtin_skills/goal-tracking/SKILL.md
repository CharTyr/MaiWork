# 目标追踪（MaiWork 改编版）

来源与取舍：改编自 openai/skills 的 `define-goal`（Apache-2.0，原文路径
`skills/.curated/define-goal/SKILL.md`）。借它的「把模糊意图变成可度量目标」那套质量门槛，
换成 MaiWork 的目标机制：**完成标准 + 证据打勾**。上游讲的 get_goal / create_goal 那套工具
MaiWork 没有，别去找、也别假装有；MaiWork 里立目标、补标准、勾标准都由主流程驱动。

## 什么时候读这份

- 群友请 MaiWork「盯着 / 做成」一件事，要判断它能不能立成 agent 目标时；
- 目标还没有完成标准、要替它补出来时；
- 每次检查，要决定哪条标准可以勾、要不要派下级任务、下次什么时候再看时。

## MaiWork 的目标长什么样

- 一个目标 = 一句标题 + 一句内容 + **3–5 条完成标准**（每条 ≤30 字，最多 5 条）+ 一个时间要求。
- 标准是「能被证据证明已经发生」的事，不是「打算做什么」。
- 标准一旦定下来就锁住：以后每次检查只能按它勾，不许偷偷改宽或改窄。
- 勾标准必须给证据，由程序校验；给不出证据的勾一律不生效。

## 一条合格的标准要回答什么

借上游的质量门槛，逐条问：

1. 做完之后，具体哪件事会变成真的？
2. 主要产物是什么（一份清单 / 一个网页 / 一条群公告）？
3. 拿什么验证它做完了？
4. 哪些在范围内？
5. 哪些明确不在范围内（有歧义时才写）？
6. 什么情况下停下来问发起人，而不是继续硬磨？

**可度量优先，但不要装饰性精度**：能用「有没有」判的就别硬凑百分比；凑不出真数字时，
宁可用最诚实的「有 / 没有」判据，也不要编一个好看的小数。

## 什么证据才算数（勾标准的口径）

一条标准要勾，必须给下面两种证据之一：

- **哪条下级任务做完了**：`task_id` 指向那条任务，它必须挂在这个目标下、状态是已完成、
  而且有验收通过的记录。
- **群里真发生了**：`evidence` 原样引用群聊行里的原话片段，去空白后**连续 8 个字**以上一样。

不能算的：

- 只靠计划、方案、网页、说明书，**不算**「真人参与」类的标准做完了；
- 「大概 / 应该 / 差不多」这类感觉不算证据；
- 以前勾过但没留依据的条目（标「?待确认」）：你现在能按上面两条给它补上依据就补，
  补不出就别管它——不算完成，也不要去猜。

**宁可不勾，等下一次**。一条标准晚一次检查再勾，比勾错强。

## 这件事 MaiWork 能不能盯（online / human）

- `online`：完成它只需要 MaiWork 上网查、看、整理、做东西（盯版本更新、盯某个发布、
  查资料、整理成清单或网页）。
- `human`：要群友自己去投票、开档、截图、到场、动手（集体计划、约着一起玩、要大家参与的活动）。
- 判 `human` 时，尽量给一个 MaiWork 自己一次能做完的替代任务；给不出就说明只能不批。

判断只看一件事：**办成它要不要群友自己动手**。别把「群友会不会感兴趣」混进来。

## 好标准 / 坏标准

好：

> 群里至少两位群友报名参加周末的比赛（依据：群里原话）

好：

> 交出一份包含 3 个可用服务器的清单（依据：下级任务验收通过）

坏：

> 持续推进这件事（活动型，没有可验证的结果）

坏：

> 群里讨论变多（没有口径、没有出处，勾不了）

坏：

> 完成度 80%（凑出来的小数，没人能验证）

## 停下来问，不要硬磨

- 一件必须项连续做不到、且已经写清试过什么 → 转成问发起人，不要反复空转。
- 目标本身已经不可能（比如要群友到场但群里没人应）→ 说明情况、建议改标准或停掉，
  不要自己把标准改宽来「完成」它。

## 不做什么

- 不自己立目标、不改目标状态、不发群消息：这些是主流程的活，你只负责标准与证据。
- 不把「主模型 / 子 agent / 任务号」这类内部说法写进给群友看的文字里。
- 不为了凑勾而降低标准；也不因为没人回应就把标准删掉（沉默不是差评）。
