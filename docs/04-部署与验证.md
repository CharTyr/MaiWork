# 部署与验证

> 任何往线上 `plugins/` 放东西的操作都会触发全部插件热重载（见 `03-线上环境.md`）。**每次部署都要先得到用户同意。**

## 一、本地开发环境（Mac）

本仓库在外置盘 `外置盘`，文件系统是 **exFAT**，有两个坑：
1. **不支持符号链接** → Python 虚拟环境不能建在仓库里。统一用 `~/.venvs/maiwork`（已建好，含 SDK 2.8.1、pytest、aiohttp、httpx）。
2. **macOS 会给每个文件生成 `._xxx` 影子文件** → 已在 `.gitignore` 忽略；打包上传时必须排除（见下）。

```bash
# 如需重建环境
uv venv ~/.venvs/maiwork --python 3.13
VIRTUAL_ENV=~/.venvs/maiwork uv pip install \
  "maibot-plugin-sdk @ git+https://github.com/Mai-with-u/maibot-plugin-sdk.git@v2.8.1" \
  pytest pytest-asyncio aiohttp httpx

# 跑本地单测
cd <仓库目录>/plugin/CharTyr_MaiWork
~/.venvs/maiwork/bin/python -m pytest tests -q -p no:cacheprovider
```

SDK 版本必须和线上一致（2.8.1）。线上升级 SDK 后，本地也要跟着换。

## 二、宿主契约测试（在服务器上跑，不进 plugins/）

本地单测过了不代表能被 MaiBot 加载。每次改了 manifest、插件类、生命周期、组件注册，都要在**真实宿主 venv** 里跑 `tests_host/`。放在 `plugins/` 之外的临时目录跑，**不会触发热重载**：

```bash
cd <仓库目录>/plugin
COPYFILE_DISABLE=1 tar czf "$TMPDIR/mw.tgz" --exclude='._*' --exclude=__pycache__ CharTyr_MaiWork
scp -q -o KexAlgorithms=curve25519-sha256 -i ~/.ssh/<你的私钥> "$TMPDIR/mw.tgz" root@<服务器IP>:/root/maiwork-ci.tgz
ssh -o KexAlgorithms=curve25519-sha256 -i ~/.ssh/<你的私钥> root@<服务器IP> 'bash -s' <<'EOF'
mkdir -p /root/maiwork-ci && tar xzf /root/maiwork-ci.tgz -C /root/maiwork-ci
find /root/maiwork-ci -name "._*" -delete
cd /opt/MaiBot
PYTHONPATH=/opt/MaiBot .venv/bin/python /root/maiwork-ci/CharTyr_MaiWork/tests_host/test_contract.py -v
rm -r /root/maiwork-ci /root/maiwork-ci.tgz
EOF
```

2026-09-26 骨架已在线上宿主 venv 通过 4 项契约测试（manifest 无错误无警告、生命周期契约、默认关闭、加载/卸载能跑）。

⚠ 实测（2026-09-28）：契约测试在 MaiBot 目录下跑，会在 `logs/` 里多出一个 `app_<跑测试时间>.log.jsonl`（里面是插件加载/卸载测试的日志，带「config.get 调用失败」这类警告）。它**不是**线上重载，部署后检查时别把它当成新 runner 日志。

契约测试缺依赖要**直接报错**，不许 `skip`，否则会假绿。

## 三、正式部署（需要用户当次同意）

前提：本地单测和宿主契约测试都通过；用户同意；挑群里没有长任务、不忙的时候。

```bash
# 1) 先备份线上旧版本（第一次部署没有旧版就跳过）
ssh ... 'mkdir -p /root/backups/maiwork && cp -a /opt/MaiBot/plugins/CharTyr_MaiWork /root/backups/maiwork/CharTyr_MaiWork-$(date +%Y%m%d-%H%M%S)'

# 2) 打包一次传完（不要一个个文件传，每传一个都会触发一次全量重载）
COPYFILE_DISABLE=1 tar czf "$TMPDIR/mw.tgz" --exclude='._*' --exclude=__pycache__ \
  --exclude=tests --exclude=tests_host --exclude=config.toml CharTyr_MaiWork
# 先解到 plugins/ 之外，清掉影子文件，再整体移进去
#   tar xzf ... -C /root/maiwork-stage && find /root/maiwork-stage -name "._*" -delete
#   首次：mv /root/maiwork-stage/CharTyr_MaiWork plugins/ ，然后 touch plugins/CharTyr_MaiWork/_manifest.json 触发加载
#   ⚠ 实测（2026-09-27）：mv 之后**立刻** touch 不会触发——文件监控还没开始盯新目录，只记到「多了一个目录」。
#     等几秒再 touch 一次 _manifest.json，日志里看到「插件 chartyr.maiwork … 加载成功」才算装上。
#   升级：用 rsync -a（不要带 --delete 删掉线上 config.toml）把新文件覆盖进去
```

**绝对不要覆盖线上的 `plugins/CharTyr_MaiWork/config.toml`**：那里有用户填的端点、密钥和群配置。**2026-10 起网页上改的「全部配置」和「模型」也都直接写在这个文件里**（含 api_key / 管理员密码明文，用户明确同意；数据库不再存配置覆盖层，旧数据启动时一次性迁移进来），所以部署 rsync 仍然必须 `--exclude=config.toml`。配置加字段时，代码里的默认值和 `config_version` 一起升，宿主会按新结构合并旧值。网页写这个文件的完整语义（注释保留、备份、0600、写后立即生效）见 docs/02 §12.1「通用配置」。

## 四、部署后检查（每次都做）

```bash
cd /opt/MaiBot
LOG=$(ls -t logs/app_*.log.jsonl | head -1)
grep -aE "chartyr.maiwork|插件注册失败" "$LOG" | tail -5     # 应看到「加载成功」「注册完成」，没有失败
grep -ac "注册完成" "$LOG"                                    # 其他插件也都重新注册了
grep -ac "已有活动写者" "$LOG"                                # 必须是 0（A_Memorix 写锁）
grep -a "A_Memorix" "$LOG" | tail -1                         # 重载之后仍有新记录（约每 5 分钟存一次盘，等下一个 :x4:30 / :x9:30）
# ⚠ 实测（2026-09-27）：插件重载会让插件进程开一个**新的**日志文件（app_<重载时间>.log.jsonl），
#   插件的「加载成功 / 注册完成」在新文件里；A_Memorix、写锁这些主进程的记录还在原来的主日志里。
#   所以 ls -t 最新的那个不一定是你要的——两边都要看。
pgrep -af "bot.py|runner_main"                               # 进程还在
```

动过群频率的，还要回读 `frequency.get_adjust` 确认恢复。

涉及搜索的部署（2026-10 起搜索只走扩展绑定）：还要在网页「设置」页看搜索健康项——ok 应是「用 <扩展名> 的 <工具名>」；warn 的话按文案处理（没绑定 / 扩展没启用 / 没连上 / 工具不在）。从带老 `[search]` 配置的版本升级时，启动日志里应看到「[search] 迁移：…」（密钥只进数据库不落日志），且 config.toml 里的 `[search]` 段已被删掉（老文件在 `<数据目录>/config-backups/` 有备份）；也可直接看 `GET /api/extensions/search` 的 `status.ok` 应为 true。

## 五、卸载 / 回滚

- 回滚：把备份目录里的文件覆盖回去（会触发一次全量重载）。
- 完全卸载：先把 `config.toml` 里 `enabled` 改成 `false`。只改 config.toml 不会重载插件，只会调用 `on_config_update()`，所以**插件必须在 `on_config_update()` 里处理「被关掉」**：立刻撤掉所有发送闸、恢复所有群频率、停止接新活。确认生效后再删掉目录里的文件（触发一次全量重载，`on_unload` 再兜底撤一遍），最后看日志确认卸载。**不要直接 `rm -r` 整个目录**——那样不会触发卸载，插件会继续在内存里跑（M0 踩过）。

## 六、线上真群测试

- 只能在用户指定的群做（目前是 `900000001`），每次要用户当次同意。
- 会发消息、改频率、传文件的测试，测完要恢复并回读确认。
- 以 SnowLuma 日志确认消息是否真的发出。
