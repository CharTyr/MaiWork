## 阶段 0：开工准备（先做这个）

1. 按顺序读：`01-需求.md` → `02-设计.md` → `06-宿主接口事实.md` → `03-线上环境.md` → `04-部署与验证.md`。
2. 读 `reference/m0-probe/plugin.py`：M0 在线上真实跑通的探针，钩子、`send.hybrid`、群文件上传的写法可以照抄（它本身是一次性代码，不要当架构参考；里面的频率和发送闸在 v6 里不用了）。
3. 读 `reference/jev/client.py` 和 `processor.py`，了解 Jev 怎么调。
4. 跑一遍本地单测和宿主契约测试（`04-部署与验证.md` 一、二节），确认环境没问题。
5. **先做三项只读实测**（读服务器源码，不动线上），结果写进 `06`：
   - `maisaka.proactive.trigger` 在宿主里怎么处理 intent、是否受回复频率影响；
   - `person.get_value` 有哪些字段，哪个能反映「和 MaiBot 关系好」；
   - 图片、文件消息在消息库里有多少信息。

## M1：理解群（不往群里发任何消息）

目标：对一个真实服务群，产出让用户觉得「像」的群画像；网页能看、能改。

| # | 模块 | 要做的 | 验收 |
|---|---|---|---|
| 1 | `config.py` | 服务群列表、工作区绑定、`[focus]`、`[models]`、`[console]` 等（设计 §12.4）；`config_version`；`on_config_update` 里处理 `enabled` 被关掉（停后台、停读取） | 单测覆盖默认值、非法配置（重复群、空群号） |
| 2 | `host.py` | **唯一**调用 MaiBot 的地方：读消息、`knowledge.search`、`person.*`、`config.get`；统一处理返回值格式和超时 | 其他模块不得直接调 `ctx.call_capability`（写测试扫源码） |
| 3 | `store.py` | SQLite 放 `<MaiBot>/data/maiwork/maiwork.db`，WAL、单写入者；事件表 + 当前状态表同一事务；迁移版本号 | 迁移可重复执行、事件与状态一致 |
| 4 | `intake.py` | `chat.receive.after_process` 钩子：非服务群立即返回；服务群只记「有新消息」信号。**永远返回 continue**。M1 不做 @ 识别 | 单测：非服务群零读取、零调用 |
| 5 | `models.py` | OpenAI 兼容客户端，端点和模型名先读数据库里网页保存的设置、没有再读 `config.toml`（设计 §12.1）；保存后下一次调用生效；主模型、子 agent 模型各有备用；超时自己设；记录 token 用量（**端点由用户配置，没配就提示，不要自己找端点**） | 单测用假服务器：网页设置优先、改后下次调用生效、出错换备用；密钥不进日志、不进任何接口返回 |
| 6 | `profile.py` | 每群游标增量读消息 → 主模型提炼画像变更 → 入库；每周整理；管理员锁定的条目不被覆盖；关注成员候选（活跃度、人物信息、明确请求过的人） | 单测：游标去重、锁定不覆盖；线上：用户评价画像 |
| 7 | 网页 | 自带 aiohttp，默认 `127.0.0.1:18650`。两种身份：管理员密码（首次启动生成）看全部；群专属链接只看本群、只读。先做群画像（管理员可改、删、锁定）、用量、**模型设置**（测试连接、选模型、密钥只进不出，存数据库不写 `config.toml`）。界面照 `prototype/console/` 原型 | 本机 curl 能打开；没密码、错链接被拒；群链接看不到其他群和关注成员；群链接访问不了模型设置；读模型设置的接口不带密钥（写测试） |

M1 部署顺序（每一步都要用户同意）：
1. 先以 `enabled = false` 部署，确认能加载、其他插件正常。
2. 用户填好模型端点（网页设置或线上 `config.toml` 都行）、指定一个服务群，开 `enabled = true`。
3. 跑几天，用户在网页上看群画像，提修改意见。

## M2：资讯与构想

| # | 模块 | 要做的 |
|---|---|---|
| 1 | `tools.py` | 工具注册表：名字（只用字母数字下划线连字符）、参数、说明、谁能用、网页显示模板。所有工具调用经过这一个入口并落库 |
| 2 | `workers.py` | 子 agent 循环（自己的模型客户端，自己写多轮）。M2 只给搜索、取网页正文、读群画像这几样工具 |
| 3 | `scheduler.py` | 资讯时段（带随机偏移）备料、构想每日一次、主动提目标每日一次；停机错过的不补 |
| 4 | `feeds.py` | 资讯：定关注点 → 搜索 → 筛选去重打分 → 过门槛才出；构想：想法、依据、包含的项目（items） |
| 5 | `delivery.py`（一部分） | 可提起清单：`maisaka.planner.before_request` 往 MaiBot 上下文追加 ≤300 字备忘（载荷是 `items`，见 `06`），每项有有效期；每日推送上限、静默时段 |
| 6 | `topics.py` | 话题候选池（保质期）；冷场判断第 1 层（代码：睡觉时段、本群同时段节奏、间隔、上限）；第 2 层（Jev：适不适合、不适合的原因、每条候选接不接得上）；按 MaiBot 人设写开场白、`send.hybrid` 直接发（同步进 MaiBot 上下文）、素材放进可提起清单；`speaker = "maibot"` 时改用 `maisaka.proactive.trigger`；没人接则间隔加倍；效果记录 |
| 7 | 网页 | 资讯、构想页；有用 / 没用反馈；开话题记录和 Jev 判断标注 |

M2 验收：连续几天每天有资讯、没有凑数；用户标注有用率可以接受；冷场时开场白发出、确认进了 MaiBot 上下文、有人接话时 MaiBot 顺着话题聊下去；睡觉时段零开话题；和 Jev 前置插件叠加没出问题。

## M3：目标与派活

| # | 模块 | 要做的 |
|---|---|---|
| 1 | `environments/local.py` | `systemd-run --uid=maiwork` 执行，带内存、时长上限；只能写 `/home/maiwork/workspaces/<工作区>/`；自编工具放 `tools/`，依赖装工作区自己的运行环境 |
| 2 | `coordinator.py` | 主模型回合：拆任务、定完成标准、分派、验收、决定交付方式。每个工作区同一时刻一个主模型回合 |
| 3 | `goals.py` | agent 目标（闲时推进、阶段汇报、完成标准满足才结束）和成员目标（记下、提醒、问进展）；循环 30 天到期问续 |
| 4 | `intake.py` + `jev.py` | 服务群里 @ 时同步问 Jev（≤1.5 秒），识别请求；超时回落主模型慢路径；`/mw` 指令 |
| 5 | `approvals.py` | 待批请求、管理员批准 / 拒绝（网页 + 群指令）、免批配置、24 小时提醒、7 天过期、**自动审核轻活**（`auto_review.py`；2026-10） |
| 6 | `delivery.py`（其余） | 发件箱落库去重；展示类成品先发 here.now、可编辑文件先传群文件，失败互相回落（here.now 接口以官方文档为准，**不用任何账号凭据**）；传完补说明；主动开口（`maisaka.proactive.trigger`，先实测）；端点故障报错 10 分钟去重 |
| 7 | 任务生命周期 | 状态机按设计 §7.2；取消权限；晚到结果不复活 |
| 8 | 网页 | 目标、待批、任务看板和详情、工具时间线、判断记录 |

M3 验收：一个「请 MaiBot 准备一份东西」的请求走完识别 → 批准 → 干活 → 验收 → 交付（展示类走 here.now、文件类走群文件各验一次）→ MaiBot 交代；一个成员目标按时提醒；回归清单（设计 §14）里和 M3 相关的都有测试。

## 汇报方式

用户不是科班出身：先说结论和取舍，用大白话，少用内部代号；分清「实测过」和「推断」；做不到或测不了就直说，不编结果。
