# MaiWork 需求（v6）

> 这份是「要做成什么样」的清单，给开发时对照验收用。细节和理由看 `02-设计.md`；两者冲突以 `02-设计.md` 为准，并回头修正本文。
> v6 换了方向：从「群里接活的工作管线」改为「懂群、会主动做事的后台 agent」。旧方向为什么放弃见设计 §16。

## 一句话

**补全 MaiBot 的群聊生产力能力：为 MaiBot 提供一个并行的完整 Agent，理解一个群，主动找资讯、提构想、追目标，交付任何工作。**

展开说：MaiWork 是装在 MaiBot 里的一个插件：它从群聊里理解这个群在关心什么，然后**主动**在后台做事——找资讯、提构想、追目标——把结果放到网页上、传到群文件，或者让 MaiBot 在聊天里自然地提起。灵感来自 Muse 这类个人 agent 的「资讯 / 构想 / 目标」三个页面，只是服务对象从一个人换成了一个群。

## 为什么要做

- 重活（写代码、改仓库）大家会用自己的个人 agent，很少在群里派。群里真正缺的是「懂这个群、会主动替群做点事」的角色。
- MaiBot 已经有 Muse 最难攒的那一半：几个月的聊天记录、长期记忆、对群友的了解。缺的是另一半：在后台持续做事、把结果拿出来。
- MaiBot 的回复管线（planner）是为快节奏闲聊设计的，做不了跨几小时、分几步的活。MaiWork 专门做这一半，**不抢 MaiBot 的话筒**。

> 注意：**MaiWork 内部没有 planner。** 文档里说 planner 只指 MaiBot 的 planner。

## 名词（全项目只按这个意思用）

| 名称 | 意思 |
|---|---|
| MaiBot | 宿主程序和它原有的聊天回复管线。不要用「她」指代 |
| MaiWork | 本项目，一个 MaiBot 插件 |
| 服务群 | 配置里启用了 MaiWork 的群。没配置的群 MaiWork 完全不碰 |
| 群画像 | MaiWork 对一个群的理解：在聊什么、关心什么、谁在做什么、有哪些约定 |
| 关注成员 | 群里 MaiWork 额外照顾的少数人：最活跃的、和 MaiBot 关系好的、明确请 MaiBot 帮忙准备东西的 |
| 资讯 | MaiWork 按群画像找来的、值得这个群看的消息 |
| 构想 | MaiWork 按群画像提出的「可以试试 X」的点子 |
| 目标 | 需要持续追踪的事。分两种：**agent 目标**（MaiWork 自己在后台推进直到完成）和**成员目标**（群友自己的事，MaiWork 帮着记、到时提醒） |
| 主模型 | 每个群一个协调者：理解群、决定做什么、拆任务、派子 agent、验收、决定怎么交付。**不亲自干长活** |
| 子 agent | MaiWork 的执行者，受主模型协调：调研、读写文件、写代码、跑测试、自己写工具等 |
| Jev | 外部的快速判断模型（TypeSafe systemone，当前最新版本为`jev-1.13.0`），用来做便宜、快速的是非判断（如「这条 @ 是不是在请 MaiBot 准备东西」） |
| 工作区 | 一个群的资料、任务、文件、工具的归属边界。默认一群一个 |
| 管理员 | 配置里写的 bot 管理员（QQ 号），负责批准派活 |

## 必须满足的需求

### R1 只服务配置过的群

- 只有配置里列出的群是服务群；没列出的群 MaiWork **不读、不判断、不调模型、不发消息**。
- 服务对象默认是**整个群**：资讯、构想、目标都按全群的聊天内容来。
- 另外照顾少数**关注成员**：最活跃的（近 30 天发言最多的前几位）、明确请 MaiBot 为他准备东西的人、管理员手动加的人。由 MaiWork 主模型结合自己存的发言和 MaiBot 长期记忆检索，给这些人做**额外的人物画像**；画像只在网页上给管理员看，不在群里公开、不跨群使用。

### R2 理解群（一切的基础）

- 定期从 MaiBot 的消息库和长期记忆里读这个群，整理出群画像：近期话题、长期兴趣、正在做的事、约定和术语、关注成员。
- 群画像在网页上可见，管理员可以改、可以删条目；改过的以管理员为准。
- 读 MaiBot 的数据一律只读，不写 MaiBot 的记忆。

### R3 资讯

- 每个服务群每天在几个时段（如早上、下午、傍晚，时间不固定）按群画像去找值得看的消息，**没有值得看的就不出**，不凑数。
- 每条资讯：标题、几句话摘要、为什么和这个群相关、原文链接。
- 群友和管理员可以对资讯给反馈（有用 / 没用），反馈用来修正后续挑选。
- **资讯的主要出口是「冷场时由 MaiBot 开话题」**：群里安静得不寻常、又适合聊新东西时，MaiWork 挑一条合适的资讯（或构想），按 MaiBot 的人设写一句开场白直接发出去（不经过 MaiBot 的回复管线，确定会发），同时把素材交给 MaiBot，接下来的聊天由 MaiBot 接。冷场用代码按本群平时节奏算，「适不适合开、哪条接得上」由 Jev 判断。
- **睡觉时段（默认 23:00–08:00）绝对不开话题**，哪怕群里还有人在聊。
- 开话题有每日上限和最短间隔；上次没人接就隔更久再试。

### R4 构想

- 时不时按群画像和最近在做的事，提出值得试试的想法：想法是什么、为什么适合这个群、第一步怎么做。
- 构想只是建议；有人说「做吧」，就转成任务或 agent 目标（派活规则见 R6）。

### R5 目标

- **agent 目标**：有人明确要求「帮我们盯着 X / 把 X 做出来」时建立。MaiWork 在闲时静默推进，有阶段性结果就汇报，直到完成标准真的满足才结束。
- **成员目标**：群友自己的事（如「月底前交稿」），MaiWork 帮着记，按时提醒；到期问一句进展。
- 目标有完成标准、负责人、截止时间、下次检查时间，历史保留。

### R6 群里 @ 派活（需管理员批准）

- 有人在群里 @ MaiBot 请它准备东西（整理资料、做个文件、调研、写个小工具），MaiWork 识别出来记成「待批请求」。
- 默认要 **bot 管理员批准**才开工（可配置成不需要批准，或只对部分群、部分人免批）。
- 管理员可以在网页上批准 / 拒绝，也可以在群里用指令批准 / 拒绝。
- 请求人要知道状态：已记下、等批准、已开工、已完成 / 被拒。优先让 MaiBot 在回复时自然说明，必要时 MaiWork 发一句简短的固定话。
- 取消 / 暂停只限发起人、群管理和 bot 管理员。

### R7 不抢 MaiBot 的话筒

- MaiBot 照常聊天，MaiWork **不改群的回复频率、不拦截 MaiBot 的发送**。
- MaiWork 自己往群里发消息只限：冷场时开话题的一句开场白（按 MaiBot 人设写，之后的对话归 MaiBot）、交付成品的说明、派活状态的简短固定话、模型或执行环境故障的准确报错。其他想让群知道的事，交给 MaiBot 用自己的口吻说。
- MaiWork 主动推到群里的内容有每日上限和静默时段（可配置），避免刷屏。

### R8 交付

三种方式，按内容选，可以同时用：

1. **网页**：MaiWork 自己的页面，按群分「资讯 / 构想 / 目标 / 任务 / 群画像」。
2. **here.now 或群文件**，按内容类型选：
   - **展示类、可视内容**（报告页、资讯合集、图表、网页原型、带排版的总结等「打开来看」的东西）**优先做成网页匿名发到 here.now**（24 小时过期，不用账号），群里发链接；发不了再传群文件（如 HTML 文件）。
   - **要下载、要编辑的文件**（Word、表格、代码、压缩包、数据）先传群文件；传不了再发 here.now。
   - 传完都补一条说明（实测 MaiBot 不知道文件是谁发的）。here.now 过期后，网页里仍保留一份。
3. **MaiBot 顺口提起**：把要说的事交给 MaiBot，在相关话题出现时或合适的时候由 MaiBot 自然地说出来。

- 发件箱落库、去重；发送超时先查证，不盲目重发。
- 工具调用过程只进网页后台，不刷群。
- 模型端点故障：把准确错误（状态码、原文，去掉密钥）发到群里，同一群同一错误 10 分钟只发一次。

### R9 主模型 + 子 agent + 执行环境

- 默认一群一个工作区、互不相通；可以在配置里把多个群绑成一个工作区。共享工作区**默认只交付回来源群**。
- 主模型只协调、分派、验收、决定交付；实际操作都交给子 agent。
- 首版只有一层子 agent；子 agent 不能宣布任务完成，只能交回成果和证据，由主模型验收。
- 子 agent 能自己写代码、写工具；ACP（Codex / Claude Code 委派）**本期不做**，只留接口。
- 执行环境：
  - 本机：用系统用户 `maiwork` 执行（已建好），只能写 `/home/maiwork/workspaces`，带内存、时长限制，不能拖垮 MaiBot。
  - 专用 VM/VPS：配置了就用于重活。
  - Railway 临时 VM（`ssh railway.new`）：没配专用机时的默认远端，60 分钟窗口。自动化接入还没测。
- token 不设上限；网页上显示用量，可设提醒阈值，超了只提醒不暂停。

### R10 网页（控制台）

MaiWork 自带网页，默认只监听本机 `127.0.0.1:18650`（要在手机上看或给群友看，用户自己套 Cloudflare Tunnel）。

**两种身份**：
- **管理员**：输入密码后看到全部群，能批准、修改、看设置和用量。
- **群友**：打开本群专属链接（群里发 `/mw 网页` 获取），只看到本群，只读，可以给资讯、构想反馈；看不到其他群、关注成员、工具调用细节、设置和用量。管理员可随时重置群链接。

管理员要能看到：
- 每个服务群的资讯、构想、目标、任务、群画像；
- 待批请求（批准 / 拒绝）；
- 任务详情和**每个任务的工具调用细节**（工具名、输入、输出、耗时、错误）；
- 反馈（资讯、构想、Jev 判断都能标「对 / 错」或「有用 / 没用」）；
- 用量和提醒；
- **模型设置**（见 R11），管理员能在网页上直接改。

### R11 模型

MaiWork 自己配 OpenAI 兼容端点（如 NewAPI）：`base_url`、`api_key`、主模型、子 agent 模型，各可配一个出错时换用的备用模型。**不走 MaiBot 的 `[[models]]`**（宿主有 30 秒超时，而且改宿主要授权）。具体用哪个模型，用户之后自己配。

- 两个地方都能配：插件 `config.toml`（部署时的初始值），或网页设置（管理员）。网页上改过的以网页为准。
- 网页上：填端点地址和密钥，点「测试连接」拉取端点上有哪些模型，再从下拉里选主模型、子 agent 模型和备用；保存后下一次调用生效，正在跑的任务不受影响。
- 密钥只进不出：网页上只显示「已填 / 没填」，任何接口都不返回密钥，也不进日志。
- 网页保存的设置存在 `<MaiBot>/data/maiwork/`，**不写回插件的 `config.toml`**（那在 `plugins/` 下，一改就会让全部插件重载）。
- 模型没配好时，网页设置顶上提示，MaiWork 不做任何需要模型的事。
- Jev 单独连 TypeSafe，不在这里配。

## 硬约束（违反即返工）

1. **MaiBot 宿主代码零改动**。只用插件 SDK 公开的钩子和能力。
2. 插件**默认关闭**（`[plugin] enabled = false`），只服务配置里列出的群。
3. 不追求大而全，**不要臃肿**；细粒度权限这类先不做（派活审批是例外，见 R6）。但工作区隔离、资源限制、真实验收、去重属于「做对」，必须做。
4. 数据库、密钥放 `<MaiBot>/data/maiwork/`；子 agent 工作区放 `/home/maiwork/workspaces/`。**都不能放宿主 `plugins/` 目录**（那里有 `.py` 变动会让全部插件重载）。
5. 工具名只用字母、数字、下划线、连字符，不能带点。
6. 不参考、不复用用户早期的探索插件 `CharTyr_IronClaw_Bridge`、`chat_summary`。
7. 关注成员的个人画像只给管理员看，不在群里公开，不跨群泄露。

## 暂不做

ACP、细粒度权限、凭据隔离、浏览器自动化、多层子 agent、OAuth 类插件、私聊、Telegram（Telegram 适配器没开放任何 API）。
