# 开发入门

给参与开发的人（和 agent）看。用户向的介绍在仓库根的 `README.md`；开发规则和红线在 `AGENTS.md`，**动线上之前必读**。

## 文档怎么读

| 文件 | 内容 |
|---|---|
| `AGENTS.md` | 开发规则、线上红线、设计红线、分工 |
| `docs/01-需求.md` | 要做成什么样、硬约束、暂不做什么 |
| `docs/02-设计.md` | 完整设计（唯一设计依据，含已拍板决定和实测结果） |
| `docs/03-线上环境.md` | 线上 MaiBot 在哪、怎么连、热重载的坑、执行用户、测试群 |
| `docs/04-部署与验证.md` | 本地环境、宿主契约测试、部署、部署后检查、卸载 |
| `docs/05-开发计划.md` | 分阶段任务和验收标准 |
| `docs/06-宿主接口事实.md` | 已核实的 MaiBot 钩子和能力用法 |
| `docs/07-代码接口.md` | 模块之间的接口约定、网页接口和返回结构 |
| `docs/08-待你同意的事.md` | 要用户同意的部署步骤、要用户决定的事、部署记录 |

## 跑测试

```bash
cd plugin/CharTyr_MaiWork
~/.venvs/maiwork/bin/python -m pytest tests -q -p no:cacheprovider     # 本地单测
# 宿主契约测试见 docs/04-部署与验证.md 第二节（在服务器上跑，不影响线上）
```

## 目录

```text
README.md                  用户向介绍
AGENTS.md                  开发规则（给 agent 看）
docs/                      需求、设计、环境、部署、计划、接口
plugin/CharTyr_MaiWork/    插件代码（部署时整个目录放到线上 plugins/ 下）
  plugin.py                入口：两个钩子（收消息、给 MaiBot 加备忘），默认关闭
  app.py                   把各模块接起来、后台循环
  console/                 网页（后端 + static/ 前端）
  tests/                   本地单测（Mac 上跑）
  tests_host/              宿主契约测试（服务器上用 MaiBot 的 venv 跑）
prototype/console/         网页原型（真网页按它做，手机 / 平板 / 桌面三种布局）
reference/
  m0-probe/                M0 线上实测用过的探针插件：钩子、发消息、传群文件的真实写法
  jev/                     另一个插件里调用 Jev（TypeSafe）的代码，只参考调用方式
  maibot_sdk-2.8.1/        线上正在用的插件 SDK 源码副本（去掉了旧版兼容层）
```

## 本地环境说明

仓库在 exFAT 外置盘上，不支持符号链接，所以 Python 环境放在 `~/.venvs/maiwork`（Python 3.13 + SDK 2.8.1 + pytest + aiohttp + httpx）。重建方法见 `docs/04-部署与验证.md`。

exFAT 上用编辑工具新建文件可能报 ENOTSUP，新建文件改用 shell heredoc 或脚本写；留下的 `.*.tmpdir` 要删掉。

## 公开仓库

GitHub 上的公开仓库是脱敏后单独生成的一份，本地仓库没有 remote。往公开仓库推之前要重新脱敏（去掉服务器地址、QQ 号、线上环境文档等）。
