## 热重载（M0 实测，很重要）

- 插件目录里**改或删已加载插件的 `.py` / `_manifest.json`** → **全部插件**热重载一次（进程不重启，约 15 秒）。
- 只改 `config.toml` → 只调该插件的 `on_config_update()`，不重载其他插件。
- **新建一个插件目录不会触发加载**；要再改动其中一个文件（例如 `touch _manifest.json`）才会触发。
- **整个目录一次性删掉不会触发卸载**，插件会继续在内存里跑。卸载要先删目录里的文件（会触发重载），再确认日志里有卸载记录。
- 每次全量重载有小概率让 A_Memorix（长期记忆插件）写锁卡住。重载后要检查：`grep -ac "已有活动写者" <最新日志>` 应为 0，且之后仍有 `A_Memorix` 的日志。

所以：**部署一次 = 全部插件重载一次，必须先得到用户同意。**

## Jev（TypeSafe）

- 接口 `https://api.typesafe.ai/v1/systemone`，模型 `jev-1.13.0`，实测 p50 约 550ms。
- 密钥在服务器 `/root/.typesafe_key`（**不要读出来、不要打印、不要写进仓库**；代码按 `reference/jev/client.py` 的 `resolve_key()` 方式读取）。
- 调用写法参考 `reference/jev/client.py`（请求体 `{model, state, questions}`，返回 `answers`）和 `processor.py`（怎么组织 state 和 questions）。那是另一个插件 JevPreprocessor 的代码，**只参考调用方式，不要改它**。

## 执行用户 maiwork（已建好）

| 项 | 值 |
|---|---|
| 用户 | `maiwork`，uid 994，gid 984，不能登录（nologin） |
| 家目录 | `/home/maiwork` |
| 工作区根 | `/home/maiwork/workspaces`（权限 750，属 maiwork） |
| 权限边界 | `/root` 是 700，maiwork 读不到 MaiBot 的任何东西（这是故意的） |
| 执行方式 | `systemd-run --wait --collect --pipe --uid=maiwork --gid=maiwork -p MemoryMax=<如 512M> -p MemorySwapMax=0 -p RuntimeMaxSec=<秒> -- <命令>`；超限时退出码为 1，已实测 |
| 创建前的备份 | `/root/backups/etc-users-20260926-181948` |
| 退出码（2026-09-27 实测，systemd 257） | 超内存、超时 systemd-run 都退 1，**不是 137**；不加 `--quiet` 时 stderr 末尾有 `Finished with result: oom-kill / timeout / exit-code`，MaiWork 靠这一行判断。命令自己失败时退出码透传 |
| MaiWork 真代码实测（2026-09-27） | 用 `environments/local.py` 在服务器上跑：退出码透传、`HOME`=工作区（用 `--setenv`，否则是只读的 `/home/maiwork`）、只看得到本工作区、超内存 / 超时识别正确、后台进程退出码经 `runtime/logs/<标签>.exit` 读到；测试目录已删，无残留单元 |
| 隔离（2026-09-27 实测） | 加 `-p ProtectSystem=strict -p ProtectHome=read-only -p PrivateTmp=yes -p NoNewPrivileges=yes -p TemporaryFileSystem=/home/maiwork/workspaces -p BindPaths=<本工作区>` 后：别的工作区看不见、`/home/maiwork` 只读、`/tmp` 私有、本工作区可写、能出网。不加时 maiwork 能写系统 `/tmp` |
