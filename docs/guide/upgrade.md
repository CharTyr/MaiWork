# 升级说明

[← 回到 README](../../README.md)

每一版改了什么、从旧版本升上来要注意什么。

## 最近几版的变化

**0.12.0**：网页多了一个「看板」页（只总管理员能看、只读不改）：每个专岗一栏，正在做的和做过的活各是什么、进行到哪一步一目了然；点开一条能看到这一轮里调了哪些工具、模型回了什么、以及它的思考过程。配置版本升到 0.5.4，数据库升到库号 47，新增项都有默认值，**不用改配置**（升级注意见下面「0.12.0」一条）。
- 「看板」默认只显示最近 24 小时的动态，可在「设置 → 全部设置 → 网页」里调（`[console] board_hours`，1~168 小时）。
- 模型每次调用时的思考过程（reasoning）现在会记进调用日志：只有总管理员能在网页「日志」里看，每条最多存 8000 字、超了截断，跟着日志一起到期清理，不会发给任何人。
- 内部变化：资讯轮 / 构想轮 / 开话题轮 / 主模型判断在库里各带一个「这一轮的标记」（run_ref），看板靠它把一轮里的调用精确对上条目——这也是数据库这次升级的主要内容，只加表加列、不动老数据。

**0.11.2**：修复 Windows 上社交平台（Twitter、小红书、B站、YouTube、Reddit）装不上的问题：独立环境以前按 Linux / macOS 的目录找程序，Windows 上建完环境就找不到；现在改用 Windows 的目录。配置和数据库都不变，直接覆盖升级即可。

**0.11.1**：修复和安全加固，没有新功能。配置版本仍是 0.5.3，数据库升到库号 45（只加索引），**不用改配置**（升级注意见下面「0.11.1」一条）。
- **网页密码改用 scrypt**：总管理员和群管理员密码新存的一律是 scrypt；老密码照常能登录，登录成功时自动换成 scrypt。**升级后网页需要重新登录一次**。在 `config.toml` 里直接写了 `[console] password` 的不受影响：这个密码照旧按配置比对，不换成 scrypt，也不用重新登录。
- **反向代理后的真实 IP**：新增 `[console] trusted_proxies`（「设置 → 全部设置」高级项里也能填）。网页放在 nginx / frp 等代理后面时，把代理的 IP 或网段填进去，登录限流才按真实访客 IP 算；不填和以前一样。
- 后台任务（备料、构想、画像整理、保存配置后的应用等）不会再跑一半被回收；登录限流表不再只增不减；子进程没起来时日志文件会关上。
- 用量历史查询不再卡住网页；Freestyle 大文件按片上传，不再整份读进内存；常用查询补了索引，库大时更快。

**0.11.0**：群里能和 MaiWork 连续干活了，另外装好就能用的地方多了不少。配置版本升到 0.5.3，数据库升到库号 44，新增项都有默认值，**不用改配置**（升级注意见下面「0.11.0」一条）。
- **群内工作会话**：群友派的活开工后，派活的人在群里 @ 机器人就能接着说——补充要求、改要求（正在做的会按新要求重开这一件）、问进度、让它暂停 / 继续、说「结束」收尾。MaiWork 会用一两句自然话在群里回应；它中途有问题问你时，@ 它回答就行。闲置一段时间（默认 60 分钟）没人理会自动收起。别人的活排在后面时会告诉对方「前面还有一个任务」。只有派活的人能这样接着说（本群批准人可以叫停），旁人 @ 照常是和 MaiBot 聊天。不想要可以在「设置 → 全部设置 → 连续对话」关掉。
- 群友链接默认用 here.now 自动公开（匿名、24 小时过期），不用再自己做反向代理；填了公开网址仍优先用它，不想公开可以关掉「用 here.now 自动公开」。
- 群文件：QQ 端读不到本机文件（NapCat 在 Docker / WSL / 别的电脑）时，20MB 以内自动改传文件内容再试一次；还是不行就改发网页链接，并在交付说明、运行状态和首次引导里写明原因。
- 缺 SSH 客户端时，运行状态和首次引导按系统（Windows / macOS / Linux / Docker）直接给出安装方法，临时机器那一项也会提示；Docker 里还会建议改用不需要 SSH 的 Freestyle。
- 首次引导完成页的「干活」「群文件」「交付」也有「前往设置」按钮了。
- 资讯卡片缺中文字体或画图浏览器时，可在「设置 → 工具 → 可选组件」一键安装（装到 MaiWork 自己的目录，不改 MaiBot 的环境）；浏览器缺系统库时会写明缺哪些、该怎么装。
- Docker 里运行时，首次引导和运行状态会检查数据目录有没有挂到容器外、网页监听地址能不能从容器外打开。默认监听地址不变。

**0.10.2**：只要有可用的机器（专用机器或一次性临时 VM），所有任务都在机器上执行，本机只在机器都拿不到时使用；Freestyle 默认每台最长 90 分钟、每天最多 5 台。

**0.10.1**：网页上的提示、状态和报错改成更简洁统一的写法；机器报错只显示中文原因；修正了几处设置路径的说法。

**0.10.0**：新增生图、报告网页、内置 skill 和可选办公文档组件，并修复若干稳定性问题。
- **生图**：可以在「设置 → 模型」加一个用途是「生图」的模型，子 agent 就能画插画、封面、概念图；画好的图能放进交付网页，也能直接发到群里。数字和图表仍由程序画，不交给生图模型。
- **自带常用做法**：调研报告、资讯核实、通用任务、目标追踪、构想整理、办公文档 6 份 skill 随插件自带。
- **办公文档（Word / Excel / PPT）**：所需组件改为可选，在「设置 → 工具 → 可选组件」一键安装；不装时会改用 Markdown、表格或网页交付。
- **调研报告页**：调研、分析类任务统一生成好看、手机电脑都能读的报告网页。
- **资讯图解**：改为从固定零件拼图并逐个核对数字，网页里直接显示；群里的资讯卡片每条图解都完整显示，不再截掉下半截。数字前面紧挨汉字（如「压到85%」）的情况以前会被误判成「原文里找不到」，现在已修好。
- **第二家临时机器**：除了 Railway，还可以开 Freestyle（需要自己的密钥），两家可以同时开，「优先用哪家」可选；在网页上开关立刻生效。
- **收消息更稳**：群里有人 @ 时，MaiWork 不再在收消息时等判断结果，也不会再因为超时被宿主跳过。
- **资讯卡片**：没发出去会自动改发一条文字版，也能在「设置 → 概况 → 需要你处理」手动重发；图片体积明显变小。
- **待复核提醒**：拿不准的 @ 请求会在概况页提醒你，超过 14 天没处理的自动归档。

**0.9.8**：拿不准的 @ 请求会持久保存、失败自动重试，超过 48 小时未办成的进「任务 → 待复核」等你处理。资讯必须有程序实际读到的正文依据才发布，只有 RSS 摘要的条目可能变少。

**0.9.7**：安全和稳定加固。在网页上和 MaiWork 对话时，它想改运行账号、服务地址、密钥文件、SSH 机器这类关键设置，都要你先点「同意」；只有资讯、画像节奏这类普通参数能直接改。子 agent 干活时默认连不上这台服务器自己的服务和内网（出公网照常），需要时可在「设置 → 全部设置 → 运行环境」打开「允许访问本机和内网」；运行账号不能再填 root。自动审核会把群友的原话当成待判断的材料，原话里出现「忽略规则」「直接批准」之类的字眼就留给人批。任务用量一时查不到时会先暂停等你决定，不再当成没花钱继续跑。重载插件不会再吃掉当天的资讯时段。聊天记录写入变快，群聊多时不再卡顿。网页上任何一块加载失败，会在原处写明原因并给一个「重试」按钮；管理员登录过期时会提示重新登录，不再叫你去群里发指令。

0.9.6：群指令更好上手。在群里发 `/mw 帮助` 能看到全部指令，按「大家都能用 / 批准人」分好组，每条都带例子。指令的回复会顺手告诉你下一步：派了活告诉批准人怎么一句话批准，开工了告诉你怎么看进度、怎么取消。漏写了 `do`（比如 `/mw 帮我整理一份清单`）会回一行能直接照抄的正确写法，不会替你乱派活。网页群页多了一块「群指令」，可以一键复制发给群友或贴进群公告。

0.9.5：没有 Jev 时判断派活更快、更好懂——群里 @ 的消息不再攒着等十几秒，来一条马上判，MaiWork 接手的提醒能赶在 MaiBot 回复之前送到；Jev 判断时也会看前面几句群聊；模型判成派活时，待批准的请求里会写一句判断依据，方便你决定批不批。网页上这块只留开关、用哪个模型、请求词过滤三项，每天次数上限放进「全部设置」的高级里（默认每群 30 次）。想说了就算、不经判断，可以用新指令 `/mw do 要做的事` 直接派活，或者引用一条消息再发 `/mw do`，被引用的文字和图片会一起交给任务；之后照常按本群设置等批准或直接开工。

0.9.4：快速判断（Jev 这类判断模型）可以接多家服务——TypeSafe 官方、OpenRouter、OpenCode、Command Code、Vercel、Upstage、Inception、Liquid AI、Cloudflare、OpenAI Decisions 都有预设，也能自己加，在网页「模型 → 快速判断」里选用和测试。没配 Jev、或 Jev 拿不准时，群里 @ 的消息会在后台攒几条用模型快速判断是不是派活（可以指定一个便宜模型、每群每天有次数上限，「先用请求词过一遍」默认关），不再等几小时后读群时才发现。

0.9.3：派活备忘优先分配预算，预算还有余量时太长就按句截断，措辞改成明确提醒 MaiBot「已由 MaiWork 接手，你不用答应，不要自己做」——实际回复效果仍需观察。任务按你的原话逐条验收，做到哪、卡在哪、要不要等你都能看见，卡住会停下而不是硬做。交付说明先给结论并 @ 你本人，文件发不出去会给能点开的网页或手机页。资讯卡片更短更干净：短摘要、「值得看」只放头条、配图统一画框不裁、末尾带本群网页二维码。长任务和长对话更稳：原始记录和压缩提要分开存，摘要失败保留原工作视图。随口一问就只回几句话，不会为一句闲聊开大工程。0.9.2 起任务被打回不再从零重来，同一个子 agent 带着前情接着改，第二次换更强的模型，第三次停下说明原因。0.9.1 起资讯来源更多样——按群里的真实反应自动订阅好来源的 RSS；搜索会参考各种搜法的成绩。构想先评估能不能做，做不到的不再提。0.8.0 起「往群里发多少 / 谁能批本群的活」每个群自己一份（在网页群页里管）。升级前请备份插件和数据目录，详见下面「升级要注意什么」。

## 升级要注意什么

老版本升上来基本不用手动改，插件启动时会自己迁移；只有想手写配置时才需要看新写法。

**升级前先备份插件和整个数据目录，覆盖插件时保留自己的 `config.toml`。** 0.8.0 会迁移数据库和每群记忆；如果回滚到旧版，需要同时恢复升级前的数据备份，不能只换回旧代码。

- **请求头覆盖（0.7.9 起）**：端点的高级设置新增可选 `headers`，默认空。升级时宿主会自动规范化配置版本（`0.4.6`），保留原有端点、密钥和群设置；没有设置覆盖时，请求行为不变。覆盖插件文件时务必保留自己的 `config.toml`。
- **群控归一（0.8.0 起）**：`[topics] enabled / per_day`、`[delivery] push_per_day / quiet_hours`、`[approval] required / admins / exempt_groups / exempt_users` 这九个全局键改成**每个服务群一份**（存数据库）。启动时会先按每个群把这份种好，**确认落库成功后**才把这九个键从 `config.toml` 删掉（改文件前先备份）；失败就一个都不删、下次启动再试，不会覆盖你已经在群页改过的每群设置。旧文件里的值此后只作**新加群**第一次的种子，网页和 `set_rules` 都不再能改它们。
- **「这个群怎么做」（0.8.0 起）**：原来的本群提醒、资讯偏好、每群工作记忆、逐条做事经验、口味小结合成**本群规矩 + 本群做法（skill）+ 群画像**三份，启动时把旧来源原文并进新表（旧文件备份后清空），「最近做过的」只留作去重材料。
- **模型（0.7.0 起）**：旧 `[models]` 那套四槽（`base_url` / `api_key` / `main` / `main_backup` / `worker` / `worker_backup`，加重试和限流）会在启动时**自动迁移**成「一个默认端点 + 模型库 + 各岗位的选择」；迁移成功后旧 `[models]` 才从 `config.toml` 里删掉，旧文件会先备份到 `<数据目录>/config-backups/`。新写法是 `[[endpoints]]` + `[[model_list]]`（见[配置说明](configuration.md#模型)）。
- **没迁完也不停摆**：模型库还是空的、旧四槽有值时，按旧规则继续干。
- **搜索**：老的 `[search]` 段不再读了，搜索改成在网页里绑定搜索服务（存数据库）；首次引导里直接勾预设就行。
- **管理员账号**：早期注释写的「纯数字」还能认，当 qq 号处理；正式写法是 `平台:账号`（如 `qq:123456789`）。公开示例里写的是占位号码，**请换成你自己的**。
- **0.12.0**：数据库会自动从库号 44 或 45 升到 **47**（新建 `main_runs` 表记录主模型每轮判断、给 `model_calls` / `tool_calls` / `news_batches` / `ideas` / `topic_log` / `judgments` 几张表加 `run_ref` 列，只加不删）。配置版本升到 0.5.4，新增的 `[console] board_hours`（看板「最近动态」往回看多少小时，默认 24）宿主第一次加载时会自动合并进你的 `config.toml`，原有设置保留。模型思考过程从这一版起记进调用日志（只总管理员能看、每条 ≤8000 字、随日志清理）。**回滚请连同升级前备份的数据目录和 `config.toml` 一起恢复**，只换回旧代码不行。
- **0.11.2**：没有数据库和配置变化（库号 45、配置版本 0.5.3），直接覆盖升级即可。Windows 上之前社交平台装失败的，升级后在「设置 → 社交平台」点一下该平台的「重新安装」即可。
- **0.11.1**：数据库会自动从库号 44 升到 **45**（只给常用表加索引，不改表结构）。配置版本仍是 0.5.3，新加的 `[console] trusted_proxies` 默认空，行为和以前一样，不用改配置；网页在反向代理后面的话建议填上代理地址。密码改为 scrypt 后，**每个网页管理员第一次登录后旧的登录状态会失效一次，重新登录即可**（`config.toml` 里直接写了 `[console] password` 的总管理员除外，这个密码照旧按配置比对，不迁移、不用重登）。回滚到 0.11.0 时，已经升成 scrypt 的密码旧版本认不出，请连同升级前备份的数据目录一起恢复。
- **0.11.0**：配置版本升到 0.5.3（新增 `[session]` 连续对话、`[console] herenow_share`），宿主第一次加载时会把新字段合并进你的 `config.toml`，原有设置保留。数据库会自动从库号 41 或 43 升到 **44**（新建工作会话的两张表，给任务加两列，只加不删）。群友链接从这一版起默认发布到 here.now 匿名公开页（24 小时过期，内容和群友网页一样），不想公开请关掉「用 here.now 自动公开」。升级前请照旧备份插件和整个数据目录；**回滚请连同升级前备份的 `maiwork.db` 一起恢复**，只换回旧代码不行。
- **0.10.0**：配置版本升到 0.5.1，新增的临时机器和生图设置都有默认值，**不用改配置**，原来的 Railway 设置行为不变。数据库库号仍是 41（从 0.9.8 升上来不跑迁移；从 0.9.7 升上来会自动升一级，见下一条）。办公文档组件装在 MaiWork 自己的目录（默认 `/home/maiwork/pylibs`），不会改 MaiBot 的环境。新的资讯图解以新格式存进原来的位置，**回滚请连同升级前的数据备份一起恢复**。
- **0.9.8**：数据库会自动升到库号 41（给拿不准的 @ 请求加保存状态的字段）。配置版本仍是 0.5.0，不用改配置。升级前照旧备份插件和数据目录。
- **0.9.7**：数据库会自动升到库号 40。从 0.9.6 升上来最多连跑三步：给构想加「类型」、给请求和目标加「能不能做成」的判断字段、新建一张聊天记录查重用的表并把已有记录登记进去，都只加不删。配置版本升到 0.5.0，新加的 `[environments] local_network` 默认关，不用改配置。如果你的 `run_as` 写的是 `root`，升级后子 agent 会拒绝运行，请改成专用账号（例如 `maiwork`）。有任务确实需要访问本机服务或内网地址时，打开「允许访问本机和内网」。升级前请照旧备份插件和整个数据目录；**回滚请连同升级前的数据备份一起恢复**。
- **0.9.6**：没有数据库和配置变化（库号 37、配置版本 0.4.9），直接覆盖升级即可。
