# 功能详解

[← 回到 README](../../README.md)

MaiWork 各项功能具体怎么工作。

## 资讯
每天几个时段（默认 08:30 / 14:00 / 19:00），先从群聊里定下 3–5 个搜索方向，再让子 agent 上网找、主模型逐条打分。
- **去重**：同一件事（哪怕换了网站、换了标题）不会发第二次。
- **不钻牛角尖**：同一个话题 3 天内最多 3 条，搜索方向会有意往外拓展。
- **只要新的**：超过 7 天的旧闻直接丢掉。
- **支持 RSS**：在网页上给群加 RSS 源，每轮最多拿 6 条新条目一起参加评选（同样要过去重和打分）。
- **自动找好来源（0.9 起）**：群里反应好的来源会被自动订阅 RSS（有试用期，没用的自动退订）；每周还会列一次本领域的一手来源、专门搜一次博客 / newsletter，验证能订才订。网页上能看到每个源的成绩、为什么订，以及每个群近 14 天入选资讯里有多少来自好来源。

## 构想与目标
- **构想**：写清楚包含哪几件事；挑中想要的，就能开任务或立目标。
- **目标**：需要长期推进的事，MaiWork 定期检查、自己往前做。有人明确要求「帮我们盯着 X / 把 X 做出来」时就立一个（要管理员批准）。

## 任务
群友直接 @MaiBot 说要做什么。MaiWork 接下来 → 主模型拆活、派子 agent 去做 → 做完主模型先验收 → 通过群文件、临时网页（here.now）交付，或者让 MaiBot 聊天时提一句。
- **打回了接着改（0.9.2 起）**：验收没过，交回给同一个子 agent，它记得自己查过、做过什么，接着改；第二次还没过，先把前情压成提要，换「做不动时换用」的模型接着改（网页「设置 → 专岗」里选，没选就用主模型的模型）；第三次还没过就停下，说清原因。主模型只排计划和验收，不亲自干活。
- **一步一步派**：主模型看了交回的结果，可以让同一个子 agent 接着做下一步（比如先调研、再做页面），不算打回。
- **可以提异议**：子 agent 觉得要求本身有问题（做不到、前后矛盾、有更好的做法），先做能做的，再把理由和建议交上来，主模型必须表态。管理员在任务详情「返工和换手」里看得到每一次。

## 开话题
群里安静太久时，从资讯和构想里挑合适的内容开一句话题，后面的聊天交给 MaiBot。

## 图解和评价
- **图解**：没配图、数字又多的资讯，MaiWork 会画一张小数据图放在配图的位置（有的能点标签切换）。图上的每个数字都要能在原文里找到，对不上就不放；每群每天最多 3 张，可以在网页规则里改或关掉。
- **评价**：觉得哪条资讯不好，点「评价」挑理由（太旧了、没什么用、质量不高……），还可以补一句。下一轮找资讯会照着改。

## 资讯卡片、构想提一嘴（每个群单独开，默认关）
- **资讯卡片**：每批资讯出来后，挑最值得看的 1~3 条做成一张卡片图发到群里，附本群网页链接。
- **构想提一嘴**：想到新构想时，在群里用一两句话提一下；给某位群友的构想会 @ ta，但不会说出是怎么想到 ta 的。
- 这两个开关和「冷场开话题」共用**一个**每天主动发送总上限（默认 3 条，可改），睡觉时段不发。都在网页「群」页的「往群里发」里开。

## 网页控制台
- **资讯 / 构想 / 在做的事**：任务、持续目标和提醒合在一页；群友用本群链接就能看，管理员能批准、反馈有没有用。
- **群**：MaiWork 眼里这个群的样子（群画像、关注成员），加上**本群规矩**（你定的，它必须照做）和**本群做法**（它自己总结的做事经验）。总管理员和本群群管理员能看能改，群友只看得到群画像。
- **和 MaiWork 聊**：管理员直接问进度、提要求、调整做法。
- **设置**：模型（端点 + 模型库）、专岗、群链接与群管理员、扩展（搜索 / MCP / skill）、干活用的机器、用量与日志等。派活批准和推送节奏改成每个群自己一份，在**群页**里改。
