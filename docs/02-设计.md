## 1. 定位与术语

**MaiWork 是 MaiBot 背后的一个「后台大脑」：理解群 → 主动找资讯、提构想、追目标、接批准过的活 → 把结果交出来。**

名字沿用 MaiWork：前台是懂群、主动做事，背后撑着的始终是一套完整的 agent 执行环境（主模型 + 子 agent + 执行环境 + 验收）。

为什么是这个形态：
- 重活大家会交给自己的个人 agent，很少在群里派。群里缺的是「懂这个群、会主动替群做点事」的角色。
- MaiBot 已经有最难攒的一半：几个月的聊天记录、长期记忆、对群友的了解。MaiWork 补另一半：在后台持续做事、把结果拿出来。
- MaiBot 的 planner 面向快节奏闲聊，几秒内要决定回不回、回什么，做不了跨几小时的活。MaiWork 在后台做这些，**聊天还是 MaiBot 的**：MaiWork 最多开个头（冷场时一句开场白），接下来的对话归 MaiBot。

| 名称 | 含义（全文只按这个用） |
|---|---|
| MaiBot | 宿主和它原有的群聊回复管线。本文说 planner，只指 MaiBot 的 planner |
| 服务群 | 配置里启用了 MaiWork 的群 |
| 群画像 | MaiWork 对一个群的理解（§3） |
| 关注成员 | 群里额外照顾的少数人（§3.2） |
| 资讯 / 构想 / 目标 | MaiWork 的三类主动产出（§4） |
| 待批请求 | 群友 @ 派的活，等管理员批准（§5） |
| 主模型 | 每个工作区一个协调者：理解群、决定做什么、拆任务、分派、验收、决定怎么交付。不亲自干长活 |
| 子 agent | MaiWork 的执行者，受主模型协调：调研、读写文件、写代码、跑测试、写工具 |
| ACP agent | 外部编码执行者（Codex / Claude Code），算子 agent 的一种；本期不做 |
| Jev | 快速是非 / 选择判断器：@ 请求识别（§5.1）、冷场开话题（§4.4） |
| 工作区 | 群画像、产出、任务、文件、自编工具的归属边界 |
| 执行环境 | 命令实际跑在哪：本机、专用 VM/VPS、Railway 临时 VM |
| 管理员 | 配置里的 bot 管理员（QQ 号），负责批准派活、修改群画像 |

## 2. 一条群消息去哪里

| 情况 | MaiWork 做什么 | MaiBot |
|---|---|---|
| 非服务群的任何消息 | 钩子立即返回，什么都不做 | 照常 |
| 服务群的普通消息 | 钩子立即返回，只记一个「有新消息」的信号；内容之后从消息库读 | 照常 |
| 服务群里 @ MaiBot | 同步问 Jev「是不是在请 MaiBot 准备东西 / 设目标 / 设提醒」（≤1.5 秒）。是 → 记成待批请求，并给 MaiBot 留一句说明（§6.3），让它回复时自然交代状态 | 照常回复 |
| 服务群里的 `/mw` 指令 | MaiWork 处理并回一句固定话（§5.3） | 〔待实测〕会不会也回一句；给 MaiBot 留说明「这是 MaiWork 指令，已处理」 |
| 机器人自己发的消息 | 不当成请求 | — |

- **分流在最前面**：先看是不是服务群，不是就什么都不做。
- **收消息的钩子永远不中止**。中止会让消息不入库，MaiBot 的上下文和记忆就缺了这条。
- 服务群里被 @ 时，MaiBot 最多晚 1.5 秒开始处理（M0 实测钩子开销可以忽略）。
- 从讨论里冒出来的需求（没 @、比如「谁整理一下」），由主模型定期读群时发现（§3.1），同样走待批流程（§5）。

## 3. 理解群

### 3.1 群画像

- **来源**：MaiBot 的消息库（`message.get_by_time_in_chat` 按群、时间段读〔已验证〕）、长期记忆（`knowledge.search`，限本群〔已验证〕）。只读。
- **内容**：近期话题、长期兴趣、正在做的事和进展、约定和术语、常用资源、关注成员。
- **怎么更新**：每群一个游标增量读新消息（有新消息最多 60 秒读一次，没有就按 `[profile] read_interval_minutes`）；攒够一批（或每几个小时）就丢给后台长任务交主模型提炼成「画像变更」——不在后台循环里等它，发件箱、提醒、开话题不被卡住；每周整体整理一次（同一个后台任务里），去掉过时的。
- **存哪**：数据库存结构化条目（每条带来源消息、时间、置信度），工作区里同步一份 `PROFILE.md` 给子 agent 读。
- **管理员可改**：网页上能改、删、锁定条目；改过的以管理员为准，模型不会再覆盖。
- 主模型读群时顺带发现：待办、有人请帮忙、有人说了截止时间 → 分别转成待批请求或成员目标（成员目标不需要批准）。只收明确对 MaiBot / 机器人说的请求（@ 了它、点名它、或明确说「帮我整理 / 提醒我」），泛泛的「谁来整理一下」不收；@ 了但 Jev 没判出来的那些（`pending_asks` 里攒着）在提示词里标出来请它判，判过标 handled，同一消息不重复落地。
- 引用关系消息库里不记（M0 已验证），MaiWork 自己从原始消息里解析；图片、文件在消息库里的完整程度〔待实测〕。

### 3.2 关注成员

- 候选三类：
  1. 最活跃的：近 30 天发言数排前几；
  2. 明确请 MaiBot 准备东西的人（提过请求）：自动加入，一段时间没再互动就移出；
  3. 管理员手动加的人（管理员加的），永远不被挤掉。
  曾经的「和 MaiBot 聊得多」一类已退役（2026-09-27）：MaiBot 的 person 字段里没有反映关系好坏的字段、A_Memorix 的人物画像插件读不到（见 `06`）；`member_interactions` 的互动计数数据保留，只是不再用来挑人。
- 每群默认最多 5 人，可配置；管理员可手动加减、可关掉个人画像。
- **额外的人物画像**（personal_profile 开着才有）：由 MaiWork 主模型结合两类素材来做——MaiWork 自己存的发言（新表 `focus_messages`，每人只留最近 14 天、最多 300 条）+ MaiBot 长期记忆检索（`knowledge.search` 不传 `person_id`，检索文本当作「可能不准、可能混进别人事」的参考进提示词）。产出 `{summary, doing, cares, asked, style}` 存 `focus_members.persona`，note 同步成 summary。后台循环每群每轮最多重刷一人：距上次 ≥24 小时且自上次以来新消息 ≥5 条才算到期。**只在网页上给管理员看**，不出现在群消息 / 群画像 / PROFILE-*.md / 任何发给群友的文字的提示词里，不跨群。只记和「能帮他什么」有关的，不记隐私（住址、电话、感情、健康、收入等）。
- 关注成员可以得到个人向的资讯和构想，交付方式同样受 §6 约束（在群里提起时不暴露画像细节）。
  （2026-09-30 落地，个人向产出）：只对当前关注成员、`personal_profile` 开着、画像已建出来的人做；默认开着（`[focus] personal_feeds`，关掉就不出）。用他的画像（doing/cares/asked）定 1–2 个关注点，走和群向资讯同一套搜索与质量门槛，只是相关度盯着「和这个人做的/关心的事」（要能指回他的画像条目）；写法是写给本人的「你在弄 X，这个可能用得上……」，reason 里说他前几天提过什么时**只能引用他本人在群里公开说过的话**。每人每天最多 1 次、每次最多 3 条（`[focus] personal_per_day`），只在北京时间 9:00–22:00 之间跑；每次可顺带 0–1 条「我可以帮你……」的个人向构想（2026-09-28 起放在「构想」页里，和面向全群的构想排在一起，群友也看得到——本来就是从群聊里来的；卡片底部带「想给 某人」的头像 + 名字，群友版没有头像图、也不带 basis（那是画像摘要）；关注成员卡片里只留给他找的资讯。个人向**资讯**仍然只给管理员）。 **个人向条目不跨人、不跨群，永远不进群资讯视图、群友视图、话题候选池和「群友聊起时接上」的候选**，只给本人和管理员在网页上看（管理员网页 `focus[].personal`）。管理员看了觉得合适，可以点「在群里提给他」：只往本群可提起清单（§6.3）加一句「@某人 可能会对这个感兴趣：标题（链接）。提的时候别说 MaiWork 怎么知道他关心这个。」（有效 6 小时、文字过隐私闸、不直接发群消息），由 MaiBot 在合适的时候顺口提起。

## 4. 主动产出

所有主动产出都遵守两条：**宁缺毋滥**（没有值得的就不出）、**不刷屏**（推到群里的有上限，见 §6.4）。

### 4.1 资讯

- **节奏**：每群每天几个时段（默认早、午后、傍晚三个，每次随机偏移半小时内）去「备料」，停机错过的不补。备好的资讯进网页，同时进本群的**话题候选池**（§4.4），不在时段里直接往群里推。
- **流程**：主模型按群画像定几个关注点 → 子 agent 搜索、取正文（资讯和「好文」两类都找）→ 按下面的**质量标准**三道门槛筛。
- **每条资讯**：标题、2–4 句摘要、为什么和这个群相关、原文链接、来源时间。
- **个人向资讯**（2026-09-30）：给「有画像的关注成员」的资讯不走这里的时间表和「群相关」打分，见 §3.2「个人向产出」——搜索子 agent 与质量标准（硬性淘汰 + 第二道）完全复用本节这套，只是相关度改成「和这个人做的/关心的事相关」；产物**不进**本节的网页群视图、话题候选池和「群友聊起时接上」候选（库里靠 `news_items.target_user_id` 非空标记并统一过滤）。
- **两类**：**资讯**（新闻、发布、动态，看新不新）和**好文**（教程、好文章、工具介绍，不看新不新，只核对「现在还适用」：版本、价格、接口有没有过时）。网页上分两栏。
- **RSS 资讯源**（2026-10 新增）：每群可挂 ≤20 个 RSS 源（kv["feeds.rss.<群号>"]，含 Atom）；**取回的条目交进子 agent 的搜索 brief 做「优先看这些链接」**，由子 agent fetch_page 打开后按原流程交回——和搜索候选走同一套质量标准（不另开绿灯），sources.site 显示源标题；取失败只记 last_error，不拖垮这轮备料。响应 ≤2MB、含 <!DOCTYPE 一律不要（禁用外部实体）、每源每轮最多 10 条、超时 15s。

#### 质量标准（2026-09-27 与用户定）

第一道 · 硬性淘汰（不管分数，一律不上）：
1. 没有原文链接，或原文打不开、要登录、要付费。
2. 和本群最近 14 天已出的重复（链接相同，或标题 / 讲的事高度相似）。
3. 摘要在原文里找不到依据（模型判「不扎实」）。
4. 来源在屏蔽名单里：配置 `[feeds] blocked_domains` + 管理员在网页上屏蔽的；被标「没用」累计多的来源自动降权。
5. 标题党、软文广告、营销号、纯情绪没事实（模型判「垃圾」并写原因）。

第二道 · 上网页：主模型按 5 项、每项 1–5 分打：信息量（新事实而非旧闻重炒）、来源等级（官方 / 一手 > 权威媒体 > 个人博客 > 二手转述）、和群的相关度（**必须指出对应的群画像条目**，指不出最多 2 分）、时效（好文改成「现在还适用」）、值不值得聊。平均 ≥3 且相关度 ≥3 才上网页。
- 每轮最多 10 条，**尽量不同质化**：每条带一个话题标签，同一话题最多 2 条、同一来源网站最多 3 条，超出的留分高的。
- 政治、争议话题可以上，但**适当少量**：每轮最多 1 条，并且**不进群里开话题的候选**。

第三道 · 进群里开话题的候选（更严）：平均 ≥4、相关度 ≥4、值得聊 ≥4、资讯要 48 小时内；好文和争议话题不进。

被筛掉的：每条都记下卡在哪一道、原因、分数，管理员在网页「被筛掉的」一栏可看，并能一键屏蔽来源，方便调标准。群友看不到这一栏。

#### 写法：要有人味（2026-09-27 与用户定，参考 Muse 的资讯页）

MaiWork 是 MaiBot 的一环，资讯页上也要像 MaiBot 在跟这个群说话，不是甩链接。
- **正文**：按 MaiBot 的人设口吻写（读 `config.get` 的昵称、人格、说话风格），像跟熟人讲「开法很轻：……」；关键处直接嵌原文链接（只允许 http(s) 链接，网页端安全渲染）；有原文封面图就配图（取原文的 og:image，没有就不配，**不生成假图**）。
- **我发这条的原因**：第一人称，必须落到群里真实发生过的事——**什么时候聊过**（引用群里的原话片段和时间，能点回去）、**谁可能需要**（可以点名群友，依据只能是他在群里公开说过的话；关注成员的私下人物画像**不能**用来写这段）、和群画像哪条对上。找不到真实依据就老实写泛一点，不编。
- **不同角度**：每轮可以留一两个位置给「不同角度 / 反方观点」的来源，避免回音壁；网页上标「换个角度」。
- **实测过再发是加分项，不是门槛**：主模型自己判断哪条值得实测（工具、命令、开源项目、「一行命令就能……」这类），**只在 railway.new 的一次性 VM 里测**（§9.1），不在本机测。测过的在帖子里加「我试了一下」：做了什么、结果、坑。测不通就如实写「我试了，跑不通」或不发；没测的只要过质量标准照样上网页。
- **资讯偏好**：资讯页顶部，管理员可写一句「这个群想看什么、不想看什么」，每轮备料都带上这句。
- **讨论（群友版）**：每条有「想在群里聊」按钮，计数；票多的优先进开话题候选池，并且让 MaiBot 在群里聊到相关话题时能接上（§6.3「按话题接上」）。
- **群友自己聊起时接得上**：MaiWork 保存服务群最近 14 天发言的只读副本（全文检索）；每条资讯、好文、构想带一组关键词；MaiBot 每一轮回复前（`maisaka.planner.before_request`），代码用最近几条群消息去匹配这些关键词，命中就把那条内容的要点、链接、「为什么」放进备忘，让 MaiBot 能顺着接。纯代码匹配，不调模型，不拖慢 MaiBot。
- **构想不吹牛**：每条构想标可行性（能做 / 可能能做 / 需要你提供什么），写成「我可以……」的，最好先试跑一次再展示。
- **反馈**：网页上可标「有用 / 没用」；群里有人接着聊、说「这个有意思」也算正反馈（能观察到的才算）。反馈用来调关注点和门槛。
- **进群**：两条路。① 群里冷场时，由 MaiBot 拿候选资讯主动开话题（§4.4）；② 群里正好聊到相关话题时，通过「可提起清单」（§6.3）让 MaiBot 顺口提起。

### 4.2 构想

- **节奏**：每群每天最多一次，挑闲时生成；群画像有明显变化时（新项目、新兴趣）可以额外触发。
- **每条构想**：想法是什么、为什么适合这个群（引用画像依据）、第一步怎么做、大概要多少功夫。需要时先派子 agent 做个小调研或小验证。
- **转成活**：有人说「做吧」→ 转成任务或 agent 目标，走 §5 的批准规则。
- 适合拿来聊的构想也进话题候选池（§4.4）。

### 4.3 目标

| 种类 | 谁的事 | MaiWork 做什么 | 要批准吗 |
|---|---|---|---|
| agent 目标 | 群请 MaiWork 盯着或做出来的事 | 闲时静默推进（定时唤醒、按需派子 agent），有阶段性结果就汇报，完成标准真的满足才结束 | 要（同 §5） |
| 成员目标 | 群友自己的事 | 记下、到时提醒、到期问进展 | 不要 |

- 目标 = 完成标准 + 负责人 + 截止时间 + 下次检查时间 + 下级任务。
- 定时唤醒主模型检查进展，需要就再派任务；没有新信息就等下一次，不空转。
- **报平安**（2026-09-27 定，吸取 Muse「监控 15 分钟后悄悄停了还不报错」的教训）：每个进行中的 agent 目标每次检查都记一次心跳；超过预定检查时间 2 倍还没心跳、或连续 3 次检查出错，网页上标红「卡住了」并写原因，同时在网页总览提示管理员。
- 提醒和循环按北京时间；停机期间错过的只补一次。
- 循环类目标默认 30 天后停，到期前在群里问一句要不要续。

### 4.4 冷场时由 MaiBot 开话题

资讯和构想的主要出口：群里冷场、又适合聊点新东西时，让 MaiBot 用自己的口吻抛出一个话题。

**话题候选池**：每群一个。资讯、适合聊的构想进池，带保质期（默认 12 小时），过期丢弃；用过的不再用。

**判断分两层**：

| 层 | 谁做 | 判什么 |
|---|---|---|
| 1. 是不是冷场 | 代码（查消息库，不调模型） | 不在睡觉时段；安静时长明显超过本群这个钟点的平常节奏（按近几周同时段的发言频率算）；本群这个钟点平时是有人的；距上次开话题够久；今天还没到上限 |
| 2. 适不适合开 | Jev（约 0.5 秒） | 是非题「现在适合抛一个新话题吗」；选择题「不合适的原因：人都走了 / 有问题还没人回 / 气氛不对（争执、严肃事）/ 可以开」；对每条候选问「能不能自然接上最近的聊天、这个群会不会感兴趣」 |

- 第 1 层不过就不调 Jev，省调用；第 2 层只在冷场时才问，频率很低。
- 两层都过 → 选分最高的候选，**由 MaiWork 自己发出开场白**（`send.hybrid`，同一个机器人账号），不经过 MaiBot 的回复管线：
  1. **写开场白**：主模型按 MaiBot 的人设写一两句口语化的开场（读 `config.get` 的 `bot.nickname`、`personality.personality`、`personality.reply_style`〔键名读过线上配置，读取待实测〕，再参考 MaiBot 最近在本群的几条发言找语气）。纯文本、短、像随口一提；链接最多一个；不写「据报道」「以下是今日资讯」这类播报腔。
  2. **发出去**：`send.hybrid` 带 `sync_to_maisaka_history=True`、`storage_message=True`，这条话进消息库，也进 MaiBot 的上下文〔M0 已验证〕，MaiBot 会把它当成自己刚说的话。
  3. **把素材交给 MaiBot**：同时把这条资讯的要点、链接、为什么挑它放进「可提起清单」（§6.3），有效期拉长到几个小时。有人接话时，MaiBot 知道自己在聊什么，能接得下去。
  4. **后续对话归 MaiBot**：MaiWork 只负责开这一句，接下来谁回、怎么聊都是 MaiBot 的事，MaiWork 不跟着说。
- 为什么不让 MaiBot 自己开口：`maisaka.proactive.trigger` 最终说不说由 MaiBot 自己决定（已读源码），时机和措辞都不可控。自己发更确定。`maisaka.proactive.trigger` 保留为配置选项（`speaker = "maibot"`），以后想对比效果可以切。
- 语气按人设写即可，不另设人工审核。〔待实测，M2 验收项〕开场白确实进了 MaiBot 的上下文，有人接话时 MaiBot 能顺着这个话题继续聊。
- **睡觉时段绝对不开**：默认 23:00–08:00（北京时间，可配置）。哪怕那时群里有人在聊，也不开话题；这个时段里备好的料等天亮后按正常规则再判。
- **节制**：每群每天开话题有上限（默认 2 次，计入 §6.4 的每日推送上限）；两次之间至少隔几个小时（默认 3 小时）。上一次开的话题 10 分钟内没人接 → 下次间隔加倍，不对着空屋子说话。
- **效果记录**：每次开话题后 10 分钟内有没有人接、接了几条，记下来，作为资讯挑得好不好的反馈；Jev 的每次判断落库，网页可标对 / 错。
- **和 MaiBot 自带功能不撞车**：读源码没发现 MaiBot 有「冷场自己开话题」的功能（见 `06`），所以不存在双开。宿主升级后要重新查。

## 5. 群里 @ 派活与批准

### 5.1 识别

- 服务群里 @ MaiBot 的消息：`chat.receive.after_process` 钩子（blocking，≤1.5 秒）问 Jev 一个固定选项题：`请求准备东西 / 设目标 / 设提醒 / 都不是`。Jev 明确判「都不是」且把握够就是正常闲聊，什么都不记。
- Jev 不可用 / 超时 / 失败 / 把握不够：放行，这条存进 `pending_asks` 表，交给主模型下一次读群时再判断（慢一些，但不会丢）；判过标 handled，同一消息不重复建请求。
- 主模型读群时也会从没 @ 的讨论里发现请求（只收明确对它说的）。

### 5.2 批准

- 需要批准的：群友派的任务、agent 目标、构想转成的活。**不需要批准的**：MaiWork 自己的资讯和构想（轻量调研）、成员目标（提醒）。
- 配置：`required`（默认 true）、管理员名单、免批群、免批人。
- 批准途径：网页上的「待批」列表；或管理员在群里用指令（§5.3）。
- 请求人能知道状态：记下时，通过 §6.3 让 MaiBot 在回复里顺带交代；批准 / 拒绝 / 开工 / 完成时，MaiWork 发一句简短固定话或让 MaiBot 提起（可配置）。
- 待批超过 24 小时没人处理：网页标红，在群里提醒一次管理员（可关）。超过 7 天自动过期。
- 取消 / 暂停只限发起人、群管理（从适配器的群成员信息读）、bot 管理员；网页上总能取消。注意「想要这个」这类从网页发起的请求没有对应的群友身份（发起人一栏是「群友（网页）」），发起人自己没法用 `/mw` 取消——网页发起的请求只能由群管理和 bot 管理员取消。

### 5.3 指令

| 指令 | 谁能用 | 作用 |
|---|---|---|
| `/mw` | 任何人 | 列出本群进行中的目标、任务、待批请求（简短） |
| `/mw 网页` | 任何人 | 回复本群的网页链接（只能看本群） |
| `/mw 批准 <ID>` / `/mw 拒绝 <ID>` | bot 管理员 | 批准 / 拒绝待批请求 |
| `/mw 取消 <ID>` | 发起人、群管理、bot 管理员 | 取消任务或目标 |

- 只在服务群响应；回复是固定文本，不调模型。不带 ID 且只有一个候选时直接处理，多个时列出让人选。

## 6. 交付

### 6.1 网页

MaiWork 自己的页面（§11），所有产出都会在这里，按群分页。群友用本群专属链接只能看到本群；管理员看全部。

### 6.2 here.now / 群文件

按成品类型选首选渠道：

| 成品类型 | 例子 | 首选 | 回落 |
|---|---|---|---|
| 展示类、可视内容（「打开来看」） | 报告页、资讯合集、图表、网页原型、带排版的总结、图片集 | here.now 匿名页 | 群文件（打包成 HTML 或图片） |
| 要下载、要编辑的文件 | Word、表格、代码、压缩包、原始数据 | 群文件 | here.now（作为附件页） |

- here.now：匿名发布（24 小时过期，不用任何账号凭据），群里发链接加一句说明。子 agent 产出展示类成品时，默认就做成单页 HTML（手机上能看、不依赖外部资源），方便直接发布。接口以 here.now 官方文档为准。
- 群文件〔已验证：`upload_group_file` 1.5 秒成功〕：传完补一条说明消息（MaiBot 不知道文件是谁发的，已验证）。
- 两条路都失败才只留网页，并在群里说明。
- here.now 过期后，MaiWork 网页里仍保留成品副本；有人再要，可以重新发布一次。
- 发出去的链接、文件都放进 MaiBot 的可提起清单（§6.3），有人问起时 MaiBot 知道东西在哪。

### 6.3 让 MaiBot 顺口提起

两条通道：

1. **可提起清单**（软）：用 `maisaka.planner.before_request` 钩子，往 MaiBot 这一轮的上下文追加一小段「MaiWork 备忘」（≤300 字，纯查库）：新资讯标题、目标进展、刚记下的请求状态、刚传的文件。标明「话题相关时可以提，不必每条都说」。每项有有效期（默认 2 小时或 5 轮），过期就不再给。〔已验证：能改上下文；是否真让 MaiBot 说出来待实测〕
2. **主动开口**（硬）：重要的事（目标完成、成品已交付、待批提醒）用 `maisaka.proactive.trigger` 请 MaiBot 在该群主动说一轮，意图里写清要交代什么。〔待实测：宿主怎么处理 intent、是否受回复频率影响、会不会被当成普通闲聊〕

- 如果两条通道实测都不可靠，回落为 MaiWork 自己用 `send.hybrid` 发一句（纯文本、简短）。

### 6.4 节制

- MaiWork 自己往群里发的只限：冷场开话题的开场白（§4.4）、交付说明、派活状态固定话、`/mw` 回复、故障报错。
- 主动推到群里的（开话题、主动开口、MaiWork 自发消息，不含 `/mw` 回复和报错）每群每天有上限（默认 3 条，可配置）。
- **睡觉时段**（默认 23:00–08:00，北京时间）：开话题一律不做；其他主动推送推迟到时段结束后，推迟的在网页可见。只有故障报错和用户当时正在等的交付不受限。
- 模型端点或执行环境故障：把准确错误（状态码、错误原文，去掉密钥）发到群里；同一群同一错误 10 分钟内只发一次。

### 6.5 发件箱

- 每条通知记 `待发 / 发送中 / 已发 / 不确定 / 失败`，按「对象 + 版本 + 事件类型 + 目标群」去重。发送超时先查证，查不清标「不确定」，不盲目重发；群文件上传同理（上传不幂等）。
- 任务「已完成」和通知「已发出」分开记。做完了没发出去，网页显眼标出，可手动重发。
- 插件重启后只补发没确认的，不重播全部。MaiWork 自己发的消息不会被当成新请求。

## 7. 主模型、子 agent 与任务

### 7.1 分工

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 主模型 | 读群、更新群画像、定资讯关注点、筛资讯、出构想、管目标、拆任务、分派、验收、决定交付方式；被问进度时直接查库回答 | 长时间搜索、处理文件、写代码 |
| 子 agent | 需要工具、文件或命令的一切实际操作 | 自己宣布任务完成、直接在群里发言 |
| ACP agent（以后） | 仓库级改造、多文件重构、长测试循环 | 同上 |

- 首版只有一层子 agent，子 agent 不能再派子 agent。
- 每个工作区同一时刻只有一个主模型回合在改状态；子 agent 可并行（默认每工作区 2 个，全局上限可配）。

### 7.2 任务

每个任务记录：工作区、来源（群、消息、发起人，或「MaiWork 自发」）、所属目标、目标、完成标准、输入材料、执行者、执行环境、批准记录、交付方式、需求版本。

| 状态 | 含义 |
|---|---|
| pending_approval | 等管理员批准 |
| queued | 等资源或依赖 |
| running | 子 agent 在做 |
| waiting_input | 缺信息，问题已发到群里；6 小时后提醒一次，24 小时没回复转为搁置 |
| shelved | 搁置：不再催；有人回复那条提问即恢复 |
| reviewing | 子 agent 交回，主模型验收中 |
| completed | 验收通过（有没有发出去另外记） |
| failed | 失败，原因和已有产物保留 |
| paused / cancelled / rejected | 暂停 / 取消 / 被拒 |

waiting_input / shelved 的恢复：提问发出后把那条 QQ 消息 ID 记在任务上；有人回复那条提问（或发起人 @ 机器人且群里只有他这一个等待任务）即视为回答，回答追加进需求、任务重新排队，任务详情时间线记「收到回答：前 60 字」。

- **交回要带证据**：结果摘要、产出文件、实际执行和测试输出、没解决的问题。只说「做完了」不算。
- **验收**：代码看真实测试结果；文件打开检查关键内容；对外写操作要有可核对的链接或 ID。拿不准就再派一个验证任务。
- 验收不通过 → 开新一次尝试，旧记录保留。
- 需求改了 → 先存新版本再通知执行者；旧版本的结果不能冒充满足新需求。
- 取消 → 停调度、停能停的进程；已经发生的外部操作不假装撤回；晚到的结果只记历史，不会让任务复活或再次交付。
- 长命令后台跑，完成时唤醒对应子 agent，子 agent 交回时唤醒主模型。不轮询、不空等。
- 单回合步数用完只是存进度续跑。
- token 不设硬上限。网页按工作区、任务、产出类型、模型显示用量；可设提醒阈值（每工作区每日、单任务），超出时在网页设置页醒目标出，不往群里发，不暂停。

## 8. 编码、自编工具与 ACP

- **子 agent 自己就能编码**：写脚本、处理数据、生成文档、调 CLI、修小段代码、跑测试。缺现成能力时，可以自己写工具。
- 自编工具保存在工作区 `tools/`，附说明、依赖和一次真实测试结果；好用的再整理成工具包或 skill 复用。依赖装在独立环境里，不动 MaiBot 的 venv，不写进宿主插件目录。
- **ACP 本期不做**，只在代码里留好执行者接口。以后接入的约定：
  - 只有配置了、连得上、额度够时，重编码任务才交给 Codex / Claude Code；没配或出故障，子 agent 照样做。
  - 装了不等于能用：ACP 适配器、登录状态、额度要分别探测。
  - 产物必须取回工作区，或留下可核对的仓库引用（分支、提交、PR）。
  - 连接断了先核对远端状态和已有产物，再决定是否续做，不重复提交有副作用的操作。
  - 首选官方 Python SDK `agent-client-protocol`；装不上就自己实现 JSON-RPC。

## 9. 执行环境

执行者和执行环境是两回事：子 agent 和 ACP 都可以跑在任一环境。

| 环境 | 用途 | 注意 |
|---|---|---|
| MaiBot 本机 | 搜索整理、文件处理、轻量脚本、短测试 | 用 `systemd-run --uid=maiwork` 执行，带内存、时长上限；系统只读、私有 /tmp、**只挂本工作区**（看不到别的群的工作区）〔已实测〕；不能拖垮 MaiBot（本机空闲内存约 2.3G） |
| 专用 VM / VPS | 配置后承接重活、长任务 | SSH 接入；持久 |
| Railway 临时 VM | 没配专用机时的默认远端 | 60 分钟构建窗口；不当持久存储 |

**默认选择：主模型按任务自己选本机或一次性 VM**（派活时计划 JSON 里报 `env` + `env_reason`）：默认本机（快、便宜、能直接交付）；要装一堆依赖、跑不信任的第三方代码、要 root / docker、要很多内存或长时间、要干净系统时才选 Railway 一次性 VM；选 Railway 但拿不到（同时占用 / 每天限额完 / refused）自动回落本机，并在任务 env 字段和时间线写明原因。成品最后必须用 `vm_fetch_file` 从 VM 拷回本机工作区才能交付——验收 / 交付只看本机。railway 选项只在 `[environments] railway=true`、一次性 VM 环境就位时才出现在提示词里，否则主模型不会看到。资讯、构想这类日常产出默认只用本机。

统一接口：申请、执行、后台运行、查看、取消、上传、下载、释放。换环境 = 开一次新尝试，带上已取回的进度。

### 9.1 Railway 临时 VM

- 入口：`ssh railway.new`。默认开启（没配专用机时），网页可关。
- 官方说明（[railway.new](https://railway.new)）：约 1.4 秒拿到一台 Linux VM，2 vCPU / 2 GB；构建窗口 60 分钟；之后 24 小时内可认领，不认领就连文件一起删；同一 SSH key 重连回到同一台；命令行连接的 agent 首次连接会收到 JSON（预览链接、截止时间、认领链接）；预装 Python、Node、Claude Code、Codex 等。高峰期可能暂时拿不到。
- MaiWork 在数据目录生成自己专用的 SSH key；每个工作区一台，不跨工作区复用；不靠换 key 绕开限制。
- 开工前确认剩余时间够「执行 + 导出」；过程中定期把成果、脚本、日志拉回工作区；到期前留出导出时间。到期未完成 → 标记中断，主模型决定续做或换环境。
- **预览链接在认领前只有创建者的 IP 能打开**，不能发给群友。认领 VM 或产生费用要用户确认，不自动认领。
- 〔已实测，见 `09`〕非交互 SSH 调用、文件传输、断线后进程存活、JSON 格式（不带命令连一次，JSON 在 stdout）。
- **资讯实测**（2026-09-27 定）：主模型判断某条资讯值得实测时，派子 agent 在一次性 VM 里跑；**不在本机测**。用完即弃，不做持久存储、不认领。
- 〔已实测 2026-09-27，见 `09`〕能无人值守用（本机和服务器都行）；**同一出口 IP 每天最多 3 台、同时只有 1 台能用**，一把 key 就是一台机器，没有主动销毁命令，60 分钟构建窗口。所以：**一轮备料最多开 1 台 VM，这一轮要测的（最多 2 条）在同一台里依次测**；每天实测最多用 2 台（留 1 台余量给派活），用量记在库里；拿不到机器（退出码 13、`refused`）就这轮不测，照常出资讯。

## 10. 工具、插件与群空间

工具在一个注册表里统一定义（名字、参数、说明、网页显示模板、谁能用），提示词、网页、调用记录都从这里取。工具名只用字母、数字、下划线、连字符（带点号会被模型供应商拒绝）。

| 能力 | 谁用 | 内容 |
|---|---|---|
| 群画像、产出、目标、任务 | 主模型 | 增删改查，保留历史 |
| 群聊记录、记忆 | 两者 | 读本群历史；查 MaiBot 的长期记忆（`knowledge.search`，默认限本群）〔已验证〕 |
| 交付 | 主模型 | 写网页、发布 here.now、上传群文件、加入可提起清单、请求主动开口、发简短消息 |
| 文件 | 子 agent | 工作区内读写、解析（txt/md/csv/json/html/docx/pdf） |
| 执行 | 子 agent | 短命令、后台进程、查看、取消（经执行环境） |
| 网页、搜索 | 子 agent | 网页取正文；搜索走「扩展」里绑定的那个 MCP（管理员在网页上绑定，不写死在配置） |
| 扩展 | 子 agent | SKILL.md、remote MCP、自编工具 |
| 群空间 | 主模型决定，子 agent 执行 | 群文件、公告、相册 |

**群空间**：
- 平台差异放在平台档案（`platforms/qq_onebot.py` 的 `GroupSpace`）。启动时探测：调 `api.list` 拿适配器实际开放了哪些接口（缓存 6 小时），再按群用 `group_member_role` 拿机器人身份（缓存 1 小时），**两样都满足的操作才出现**（`capabilities(group_id)`）。旧版适配器（0.8.5，没有公告/相册/文件管理接口）→ 能力全关，网页健康里标「QQ 适配器是旧版…升级到 v1.0.1 后自动开放」。
- 上游 v1.0.1 已开放公告 / 相册 / 文件管理（docs/06 末尾名单），**不用打补丁**；线上还是 0.8.5，升级后探测自动放开，不用改插件。
- 防手滑：删除 / 改名 / 移动只动机器人自己上传的文件——outbox 上传群文件成功时登记进 `group_files_owned` 表（`GroupSpace.register_owned`），动手前校验 file_id 在表里；发公告前先在群里说一句固定预告「我要发一条群公告：<前 30 字>」（走 outbox，push_kind=status），再发公告；每群每天最多 `[group_space] notice_per_day` 条（默认 1）。所有写操作记事件。
- 给主模型的工具（`tools_groupspace.py`，roles={main}，子 agent 不直接调）：`group_files_list` / `group_file_manage`（delete / rename / move / mkdir）/ `group_notice_send` / `group_album_upload`。能力不具备 → 工具返回中文原因（适配器没开放 / 机器人不是群主或管理员 / 只能动我自己传的文件）。

**插件（skill + MCP）**：MaiWork 自己加载，不挂到 MaiBot planner 上。**联网搜索不写死在配置里（2026-10）**：内置的 tavily / tavily_mcp / exa / you 全删了，搜索只用「扩展」里指定的一个 MCP 的某个工具——管理员在「设置 → 扩展」加一个带搜索工具的 MCP（如 Tavily 的托管 MCP），点「用作联网搜索」绑上即可；绑定存数据库（kv["extensions.search"] = {"mcp", "tool", "extract_tool"}），不进 config.toml；扩展被删除 / 改名时绑定跟着清掉。对搜索的额外要求（优先什么来源、避开什么）写在 AGENTS.md 里，定关注点（群向 + 个人向）和子 agent 的 system 提示都会带上。老配置里的 `[search]` 段启动时自动迁移成一个扩展 + 绑定后从 config.toml 清掉（幂等，见 docs/07 §10.3）。

#### 扩展：MCP 和 skill（2026-09-28 落地）

两种都**只注册进 MaiWork 自己的工具表**（Tools），不给 MaiBot 的 planner 注册任何组件；每次调用照常落 tool_calls 表、照常遮密钥。

- **MCP**：配置 `[[extensions.mcp]]`（name 只用字母数字下划线横线 1~32、url 必须 https://、headers 表、tools 白名单（空=全部）、roles 默认 worker 可含 main、enabled）。启动时对每个启用的端点 initialize → tools/list，工具注册成 `mcp_<name>_<工具名>`（非法字符替换成 `_`，≤64；远端给什么 inputSchema 就用什么）；调用走 tools/call，content 里的 text 拼接（截 8000 字），isError → 调用失败。**连不上不影响启动**，健康状态和 settings 里显示错误；headers 里的密钥值并进 Tools 的统一遮罩（不落 tool_calls、不进日志、网页不回显）。**网页可管理**（管理员，`/api/extensions` 系列接口）：新增 / 修改 / 删除 / 开关 / 试连。网页加的条目**存数据库不写回 config.toml**——kv["extensions.mcp"] 存条目（只存头的**名字**），每个头的值存 secrets["mcp.<名>.<头名>"]，**密钥只进不出**（网页只显示「已填」，任何响应、日志、tool_calls 都不出现值）。合并规则：网页同名 → 以网页为准；config 里的仍然生效，网页上标「来自配置文件，只能开关不能改地址」，开关存 kv["extensions.mcp.disabled"] 名单；删除只删网页加的。改 / 删 / 开关后立即重连刷新工具表，下一次调用就生效。**roles 真生效**：注册表按角色过滤（`Tools.specs(role)`），roles 含 `worker` 的工具才进主模型挑活用的「子 agent 工具名单」，roles 含 `main` 的 MCP 工具进主模型自己的工具表（排计划查资料那一回合 + 验收核对那一回合；排计划的细节见 07 §11.4）；网页新增 / 修改时 roles 必须是列表、只能含 `worker` / `main`、不能为空，不合法 400（不静默回落；没传时新增默认 worker、修改保持原值），config.toml 里管理员手写的坏值才容错回落 worker。
- **skill**：`<数据目录>/skills/<名字>/SKILL.md`（可附其他文件），管理员放置、子 agent 只读。SKILL.md 开头可有 YAML front matter（只认 `name` / `description` / `roles`，手写极简解析，不引入 yaml 库；名字一律以目录名为准）。子 agent 有两个工具：`list_skills`、`read_skill({name, file?})`（附属文件路径越界、符号链接一律拒；SKILL.md 截 40KB）。system 提示里附可用 skill 的「名字：一句描述」清单（最多 20 条）。**roles 真生效**：主模型只看到 / 只读得到 roles 含 `main` 的 skill，子 agent 只看到 / 只读得到 roles 含 `worker` 的（角色对不上当「没有这个 skill」；system 提示里的清单也只挂 worker 的）；front matter 里手写的坏值容错回落 worker，网页新增 / 修改时 roles 必须是列表、只能含 worker/main、不能为空，不合法 400（没传时新增默认 worker、修改保持原值）。skill 里的脚本不直接执行：子 agent 要用就自己 read_skill 后 write_file 到工作区再跑。**网页可管理**（管理员）：新增 / 编辑 / 删除（名字 `[A-Za-z0-9_-]{1,64}`，内容 = front matter + 正文，单个 ≤40KB，目录 0700）；网页加的记进 kv["extensions.skills.web"] 标 source=web，目录里手动放的标 file；删除拒绝符号链接、只删 skills 目录内的东西；附属文件网页只读列出，**zip 安装**（`POST /api/extensions/skills/upload`，2026-10 新增）：请求体 application/zip（≤5MB）或 multipart 字段 file；规则照通用 skill 安装规范（SKILL.md 有且只有一份（根/唯一顶层目录），名字 ^[A-Za-z0-9_-]{1,64}$，.. / 绝对路径 / 符号链接（外部属性 symlink 位）/ >200 文件 / 解压总量 >20MB / 单份 SKILL.md >40KB 一律拒，重名 409 除非 ?replace=1），解压到 `<data_dir>/skills/<名>/`（临时目录再原子替换，目录 0700，kv 标 source=web）。

**成品格式**：Markdown、CSV、HTML、Word 本机可做；Excel、PPT 等按执行环境里实际有的依赖来。

## 11. 网页

独立于 MaiBot WebUI，默认只监听本机。电脑上经 SSH 隧道打开；要在手机上看、或让群友能打开，由用户自己套 Cloudflare Tunnel 公开出去。

**两种身份**：

| | 管理员 | 群友 |
|---|---|---|
| 怎么进 | 输入管理员密码（`[console] password` 没填时首次启动随机生成，明文放在 `data/maiwork/console_password.txt`，不写回 `config.toml`） | 打开本群专属链接（网址里带一段随机码，每群不同）。群里发 `/mw 网页` 获取 |
| 看得到 | 全部服务群 | 只有本群 |
| 资讯 / 构想 / 目标 | 看 + 反馈；构想点「做这个」直接开工 | 看 + 反馈；构想点「想要这个」→ 进待批 |

- 管理员密码错误多次要限速；登录状态用会话 cookie，不在网址里带密码。
- 群友反馈不区分是谁点的（网页没有身份），只做计数参考。

| 页面 | 内容 |
|---|---|
| 总览 | 各服务群：最近资讯 / 构想数、进行中目标、待批请求、失败和待发送数；模型和执行环境是否健康；今日用量和提醒阈值 |

## 12. 实现要点

### 12.1 模型

- MaiWork 自己的配置里填 OpenAI 兼容端点（如 NewAPI）：`base_url`、`api_key`、主模型名、子 agent 模型名，可各配一个备用。**不经过 MaiBot 的模型登记**，没有插件到宿主 30 秒超时的问题。
- **网页可改**（管理员）：设置 → 模型。填端点和密钥 →「测试连接」请求端点的 `GET /models` 列出可用模型 → 下拉选主模型、子 agent 模型和各自备用 → 保存。保存前校验：地址是 http(s)、主模型和子 agent 模型必选、备用不能和原模型相同。列表里没有的旧值照样保留并标「端点里没找到」，不悄悄丢掉。
- **存哪里**（2026-10 改）：网页保存 = **直接写进插件自己的 `config.toml` 的 `[models]`**（含 api_key 明文，用户明确同意）。config.toml 是唯一真实来源，数据库不再存配置覆盖层；宿主对每个插件的 config.toml 有单独文件监控，文件变了只给这一个插件发 `on_config_update`（不会重载其他插件，详见 docs/06）。「测试连接」的可用模型列表/测试时间不是配置，存 `kv["models.checked"]`，端点一致时并进来显示。
- **生效**：`models.py` 每次发请求前读当前设置（内存缓存，保存时刷新），所以保存后下一次调用就用新的；已经发出的请求、正在跑的子 agent 用它开始时的设置跑完。
- **密钥只进不出**：接口只返回 `key_set: true/false`；密钥输入框留空表示不改；密钥不进日志、不进工具时间线、不进错误消息（报错到群里前先去掉）。
- **重试**（0.3.9）：网络错误、429、408、5xx 可以重——同一个模型最多「1 + retries」次（retries 默认 5、可在网页改，0~10），两次之间等 retry_delay_s 秒（默认 10，1~60）；429（被限流）不按这个等，改成整个端点一起歇：有 Retry-After 按它（最多 120 秒），没有按 10/20/40/60 秒递增；同一端点同时最多 max_concurrency 个请求（默认 2，1~8），可选每分钟上限 max_rpm（默认 0 = 不限），都在网页「设置 → 模型」里改；用完再换备用模型，同样规则。其他 4xx 不重试、不换备用。后台循环里直接等结果的调用（开话题开场白、@ 设提醒）固定用 retries=1，不把循环卡住。
- **看日志**：网页（只管理员）能看最近每次模型请求 / 工具调用（写 model_calls 表，留 3 天 / 2000 行；密钥绝不入库，接口兜底再遮一遍）。
- 没配好（缺端点、密钥、主模型或子 agent 模型任何一项）：网页设置顶上提示；MaiWork 不做任何要模型的事，也不往群里报错。
- 用量由 MaiWork 自己统计，显示在网页；不计入 MaiBot 的统计。
- Jev 单独直连 TypeSafe；Jev 不可用时，所有判断回落到主模型的慢路径，不影响 MaiBot。

#### 规则（网页可改，2026-10 新增）

- 主推 / 资讯 / 开话题 / 派活批准这四节里的一组规则**在网页上改**（管理员）：`[delivery] quiet_hours/push_per_day`、`[topics] enabled/per_day/min_gap_hours`、`[approval] required/admins/exempt_groups/exempt_users/remind`、`[feeds] news_slots/max_items/web_min_avg/pool_min_avg/guides`。
- **存法**：只存改过的字段，存 `kv["rules.override"]`；**网页保存的值写进数据库，不写 config.toml**（写 plugins/ 会让全部插件重载）；有效设置 = `config.toml` 被 override 覆盖，app 在 `get_settings`（唯一出口）合并一次、缓存，override 变才重建——所有模块读到的都是合并后的值（topics.enabled 关掉起下一轮立刻停）。
- **校验**：和 config.toml 同一套语义（睡觉时段 HH:MM-HH:MM、news_slots 每项 HH:MM、QQ 号纯数字、数值范围），一个字段不过整次 patch 不落库；重置一个字段恢复成 config.toml 值。
- **settings 视图 rules 摘要用有效值**；可改项 / 接口 / 值结构细节见 docs/07 §9 和 rules.py 头注释。

#### 通用配置（网页可改，2026-10 在规则之后推广）

- **config.toml 的全部配置项都能在网页改**（`/api/settings/config`，管理员；`[models]`、`[extensions]` 两节保留各自的专用页面和接口，不进通用表；`plugin.config_version` 是版本标记不列）。每个字段在 rules.py 的 `CONFIG_SCHEMA` 里登记：key（"节.字段"）、中文 label、一句大白话 help、type（bool / int / float / str / enum / list_str / secret / serve_groups / ssh_list / time_list）、min/max、options、applies（now / reload）、readonly。
- **存法**（2026-10 改）：网页改任何一项 = **直接写进插件目录下的 `config.toml`**（config_file.py：tomlkit 读-改-写，注释和格式保留；每次写前重读文件；写前把旧内容备份到 `<data_dir>/config-backups/`，只留最近 10 份、0600；写完 config.toml 保持 0600）。config.toml 是唯一真实来源，数据库不再存配置覆盖层。密钥类（`search.api_key`、`jev.api_key`、`console.password`）也写进 config.toml（明文，用户明确同意），照旧**只进不出**：接口永远不回值，只回 `{set, source: env|file|none}`；PUT 给空串/不给 = 不改，给 null = 清空（文件里写 ""）；并进 `app._known_secrets` 的遮罩。reset = 删掉这个键，回到代码默认值。
- **生效**：写完文件**立刻在本进程应用**（走和 `on_config_update` 一样的 `update_config` 路径，不等宿主的文件监控）；宿主随后再发一次同内容的 `on_config_update`，`update_config` 幂等跳过。**全部字段都热生效**（`applies` 只有 `now`，接口的 `reload_pending` 永远是 []）：`groups.serve`/`console.listen` 的即时处理本来就有；`group_space.enabled` 在 `update_config` 里做成热生效（开→关摘掉组件、关→开现建现探测）；`environments.ssh` 没有运行时消费者（ssh 环境还没做），Settings 一换自然生效。`storage.data_dir` 只读（数据目录网页不能改自己）只能改 config.toml；`plugin.enabled` 不上网页。
- **护栏**：`environments.local_mode` 网页只接受 `systemd`（`direct` 无隔离，拒绝并说明只能在文件里改）；改 `console.password` 要同时给 `current_password` 核对（config 里的密码是准；改成功后旧的自动生成密码哈希删掉，旧登录态全部失效）；校验失败一律 400 中文原因，一个字段不过整次不写文件；写文件失败（没权限、找不到文件）500/400 中文错误，数据库不留半截状态。
- **迁移**（启动时一次，幂等）：数据库里旧的 `kv["config.override"]`、secrets 的 `search_api_key`/`jev_api_key`/`console_password`/`model_api_key`、`kv["models.settings"]` → 写进 config.toml（文件里该键已有非空值且不同的以数据库为准——之前网页优先级更高），写成功后从数据库删掉；config 里配了 `console.password` 后旧的自动生成哈希一并删掉。迁移日志只打键名，不打值。
- **Jev 密钥顺序**：环境变量 `TYPESAFE_API_KEY` → config.toml 的 `[jev] api_key`（网页改的也写它）→ `key_file` → `~/.typesafe_key`。
- 旧的 `/api/settings/rules`（白名单那几项）保持兼容。

### 12.2 数据

- 数据库、密钥、发件箱放 `<MaiBot>/data/maiwork/`（root 所有）；子 agent 的工作区放 `/home/maiwork/workspaces/`（`maiwork` 所有）。
- 为什么分开：`/root` 权限是 700，`maiwork` 进不去〔已验证〕，子 agent 碰不到 MaiBot 的任何数据；插件以 root 运行，能读工作区里的成品去上传。
- 都不放宿主 `plugins/` 目录：那里任何 `.py` 变动都会重载全部插件〔已验证〕。
- 远端 VM 上的东西都是可以重新取回或重建的副本。

```text
<MaiBot>/data/maiwork/          # root
  maiwork.db
  keys/                  # Railway 等专用 SSH key
/home/maiwork/workspaces/       # maiwork
  <工作区>/
    PROFILE.md           # 群画像（给子 agent 读的副本，以数据库为准）
    tasks/<任务>/
    artifacts/           # 成品
    tools/               # 自编工具
    runtime/             # 独立运行环境
```

- SQLite 单写入者、WAL；事件和当前状态同一事务提交；事件有格式版本，库有迁移版本。
- 大日志（完整模型请求、命令输出）单独存，保留 30 天；模型请求日志（model_calls）留 3 天 / 最多 2000 行（0.3.9 起，哪个先到按哪个清）。
- 关注成员的个人画像单独表存，移除成员时一并删除。

**回归必测**：
- 非服务群：@、关键词、指令，都是零读取、零 Jev、零模型调用、零发送。
- 不抢话筒：MaiWork 从不调用改频率和发送拦截；MaiBot 在服务群照常回复。
- 推送节制：每日上限、睡觉时段生效（睡觉时段零开话题）；资讯没过门槛时当天可以一条都不出；上次话题没人接时间隔加倍。

## 16. 与 v5.4 相比

**为什么换方向**：群里很少有人派重活（大家有自己的个人 agent）；v5.4 最复杂的部分（抢话筒、模式切换）是为这类少见场景服务的。v6 改成用 MaiBot 最大的优势——懂群——去主动做事。

| v5.4 | v6.0 |
|---|---|
| 三类群 normal / mix / work | 只有「服务群」和「不服务」 |
| CHAT / WORK 模式切换，Jev 判断进出 | 删除。MaiBot 始终照常聊天 |
| 进 WORK 上两道闸（频率 0 + 发送闸） | 删除。不改频率、不拦发送 |
| `/work on / off / stop` | 改为 `/mw`、`/mw 批准 / 拒绝 / 取消` |
| 工作只从群里 @ 和讨论进来 | 主要来自 MaiWork 主动产出（资讯 / 构想 / 目标）；@ 派活保留，但默认要管理员批准 |
| MaiWork 自己在群里接话 | 说话尽量交给 MaiBot（可提起清单、主动开口）；MaiWork 只发交付说明和简短固定话 |
| 控制台是运维后台 | 网页是主要交付面：资讯、构想、目标、群画像 |
| 保留 | 主模型 + 子 agent、执行环境、自编工具、验收、发件箱、here.now、模型自配、token 不设上限 |

## 17. 身份与工作记忆（2026-10 新增）

MaiWork 以前的「记忆」全是关于群和群友的：群画像、关注成员的私下画像、14 天群聊副本、任务历史。唯独没有一个地方记「**MaiWork 自己干活学到的东西**」。现在加上，分四类文件，全部放在 `<data_dir>/identity/` 下（目录 0700），网页可编辑，不写 plugins/。

| 文件 | 记什么 | 谁写 | 谁能看到 | 进谁的提示词 |
|---|---|---|---|---|
| SOUL.md | MaiWork 说话的口吻和性格 | 首次启动从 MaiBot 同步生成一次（读 `config.get` 的 `bot.nickname`、`personality.personality`、`personality.reply_style` 和其他能读到的 `personality.*` 文字字段）；之后只有管理员点「从 MaiBot 同步」才覆盖（覆盖前旧版存 SOUL.md.bak），平时管理员手改 | 管理员 | 所有「对外写字」的提示词：资讯帖子、开场白、交付说明、构想、个人向资讯 |
| AGENTS.md | 给主模型和子 agent 的做事规矩 | 管理员（默认一份简短模板：交付前自查、不编造、做不到就说、成品放 artifacts） | 管理员 | 主模型的计划 / 验收提示、子 agent 的 system 提示 |
| MEMORY.md | 全局工作记忆：**只放和具体群、具体人无关的经验**（管理员偏好、工具 / 来源好坏、做事方法的教训） | 管理员 + 主模型（remember 工具，scope=global，受控） | 管理员 | 主模型的计划、验收、资讯定关注点和打分、构想提示 |
| memory/<群号>.md | 每群工作记忆：本群相关的经验（这个群喜欢什么交付、哪类资讯被点没用、约定俗成的做法） | 管理员 + 主模型（remember 工具，scope=group）+ 反馈自动记（纯代码，不调模型） | 管理员 | 同上，**只注入对应那个群，绝不跨群** |

四条边界（用户拍板）：

1. **每群记忆不跨群。** 这是红线：群的记忆只进那个群的提示词。别的群不喜欢深科技长视频，不代表这个群不喜欢；混过去既不尊重这个群，也泄露了「别的群说过什么」。注入时拿 group_id 对的那个群的文件，别的群的一律不进。
2. **全局记忆不许写具体的群和人。** 全局这块同时进所有群的提示词，写了「900000001 群喜欢……」就等于把一个群的事广播给所有群。代码层挡三刀：含 ≥5 位连续数字（群号 / QQ 号）就拒；含任何服务群关注成员名字、或成员名单比较全的群的成员名字就拒；写之前把每个服务群的 privacy.scrub 各过一遍（别的群的私下画像细节也不能写进去）。拦住的话术固定带「全局记忆」四个字，提醒模型「改记到本群记忆」。
3. **私下画像一事不进任何记忆。** 关注成员的 note / persona 片段（≥8 字连续）走 privacy.scrub，记本群也不行——本群记忆会进本群提示词，就算群友看不到提示词本身，模型也可能顺着说出来。
4. **主模型只能调 `remember` 工具记，受控。** scope=group/global、text ≤200 字、reason ≤60 字；同一句（去空白后相同，不看日期和原因）不重复记；格式固定「- YYYY-MM-DD 文本（原因）」；单文件超上限（16KB）从最旧的一条开始淘汰；每次真正记住落 events 事件 `memory.write`（scope、群号、文本前 40 字），网页可追溯。子 agent 没有这个工具（roles 只给 main）。

自动记的两个触发点：

- **验收通过后、交付前**（coordinator）：给主模型一次「有没有值得记的经验？」的小回合，带 remember 工具，最多 2 次调用；没有就答 `{"done": true}`。模型没配好 / identity 模块没就位 → 整个跳过，不多调一次模型。
- **资讯被标「没用」**（console 的反馈接口触发，纯代码、不调模型）：同一个话题里累计 ≥3 条被标没用 → 往本群记忆直接写一条「XX 类资讯本群不感兴趣」；同一个来源（按 sources[0].site）有 ≥3 条各自被标过没用 → 写一条「来自 XX 的资讯本群不感兴趣」。都在「确实累计到 3 次」的那个时刻落一条（当时不够以后不翻旧账），按句去重。

注入统一走 `identity.prompt_block(kind, group_id=None)`（见 docs/07 §12.5）：分块标题固定——「## MaiWork 的身份」「## 做事规矩」「## 工作记忆（全局）」「## 这个群的工作记忆」——各块内容按 UTF-8 截到上限（SOUL / AGENTS / MEMORY / 每群记忆都是 16KB）。SOUL 为空时，feeds 的写帖子逻辑回落原来直接读 `config.get` 人设的做法（老部署、未同步的行为不变）。

## 18. 管理员对话（2026-09-27 新增）

你在网页上直接和 MaiWork 的主模型说话，不用在群里 @，说的话也不进任何群。主模型能调一批**只给管理员**的工具：能读的直接读，能改的直接改，**会对外发东西、会删东西、会放宽安全设置的**先记一张「待确认」小票，你在网页上点「同意」才真动手。

**谁能用**：只有 bot 管理员（要用管理员密码登录网页）。群友链接打开看不到这一页。

主模型一共 40 个管理员工具，分三类：

| 类别 | 大白话 | 工具 |
|---|---|---|
| 读类（直接读，什么都不动） | 看服务群名单和每个群的情况、群画像、关注成员、资讯 / 构想 / 任务 / 目标 / 待批请求、MaiWork 留存的群聊记录、模型调用日志、现在的规则、身份与工作记忆、MCP 和 skill 清单。不给群号时只列**服务群**的数据——早先服务过、后来下掉的群，残留的请求和日志一律不看 | `list_groups`、`group_overview`、`read_profile`、`list_focus`、`list_news`、`list_ideas`、`list_tasks`、`task_detail`、`list_goals`、`list_requests`、`read_chat`、`read_logs`、`get_rules`、`get_identity`、`list_extensions` |
| 直接改（改 MaiWork 自己库里的东西，不用确认） | 加 / 改 / 删一条画像、手动调关注成员、写资讯偏好、加 RSS 源、屏蔽来源域名、改运行规则（放宽安全或推送节制的要确认，见右列）、改身份与工作记忆、记住一件事、开关 MCP、让某个群现在备资讯 / 出构想 / 重新整理画像、**拒绝**群友派的活、取消任务 | `profile_edit`、`focus_edit`、`set_feeds_pref`、`rss_add`、`block_domain`、`set_rules`、`identity_edit`、`remember`、`mcp_toggle`、`run_news_now`、`make_idea_now`、`refresh_profile`、`reject_request`、`cancel_task` |
| 要确认（先写小票，你点头才动） | 往群里说话、发群公告、动群文件、往群相册传图、删 RSS 源、删 skill、删网页加的 MCP、一次删多条画像、**批准**群友派的活（群友派的活只能由你本人批，模型不能替你拍板）、**派任务给子 agent**（任务开工后，做完 / 做不成 / 缺信息时 MaiWork 会自动在群里说一句——这等于间接对外说话，所以要你点头）、**立 agent 目标**（目标立下后 MaiWork 会定期检查，有进展 / 完成时会在群里说一句，同理要你点头）；另外这些规则改动也要确认：**approval 节的任何字段**（管理员名单、免批群 / 免批人、批准开关、提醒开关全算）、每天推送上限变大、睡觉时段变窄、开话题更勤（次数变多 / 间隔变短 / 从关到开） | `send_group_message`、`group_notice_send`、`group_file_manage`、`group_album_upload`、`rss_remove`、`skill_delete`、`mcp_delete`、`profile_bulk_delete`、`approve_request`、`create_task`、`create_goal`（外加放宽时的 `set_rules`） |

**要确认的动作是怎么走完的**：

1. 主模型要动手时，工具层先不动手，在库里记一张小票（工具名、**这次真正要用的全部参数**、一句中文说明），回它一句「已请求管理员确认」。对话聚焦某个群时，模型没写群号也会先把解析出来的群号补进参数再记票——卡片上看到的是哪个群，同意后动的就是哪个群。
2. 网页这段对话里出现一张卡片，你点「同意」或「拒绝」。改规则的小票摘要会列出**全部**要改的字段（`节.字段 → 新值`，名单类把成员都写出来），太长就截断但写明「共改 N 项」——绝不会摘要里只写一项、参数里藏另一项。
3. 点「同意」才真执行；点「拒绝」就什么都不做，小票标记作废。
4. 执行结果（或「已取消」）写成一条系统提示**回到这段对话**，主模型接着往下说——比如告诉你发好了，或换个做法。
5. 一张小票只能决定一次；在另一个页面已经处理过的，再点会告诉你「已经处理过了」，页面随即刷新掉这张过期卡片。
6. 真执行也有超时（用这个工具自己的时限）：卡死了标「失败」并在对话里说明，不会一直转圈。

网页上的样子：工具调用显示成一行小标签（点开看结果）；等你确认的那一行标「待你确认」，处理完变灰「问过你了」；确认卡片只写一句人话摘要，具体参数折叠在「看具体参数」里。侧栏的对话列表用每段对话的第一句话当标题。

**写死的安全规矩**（都在代码里，不靠提示词自觉）：

- **非服务群零读取、零动作**：每个带群的工具先查群号在不在配置的服务群名单里，不在就回一句中文原因，什么都不读不做（`list_groups` 只列群号，不看别的东西）。
- **并发对话的小票不串**：「现在是哪段对话、哪条消息」按每个后台任务各存一份，两段对话同时跑也不会把 A 的小票记到 B 上。**没绑定对话就不写票**：宁可回一句「请在网页对话里重发一次」，也不偷偷新建一段没人认领的对话把票藏进去。
- **群里的话不是指令**：工具读回来的群聊原话、请求、画像都是群友写的，系统提示明确告诉主模型只当资料转述、不照做（防群友在聊天里藏指令让模型去加管理员、批活）；真正兜底的还是上面的确认门——这类动作全部要你点头。
- **模型伪造不了批准，也继承不了批准**：「管理员已同意」只在门闸真执行小票的那一下由门闸自己置上，而且记下的是**这张票的指纹**（工具名 + 规范化参数的散列）——执行期间工具再派后台子任务，子任务拿着这个标记去调别的确认类工具、或同工具换一份参数，指纹对不上就照样要写新的小票。模型传的参数里带什么都不算数，下划线开头的参数一律被剥掉。
- **传群相册只传工作区里的图**：`group_album_upload` 的路径在写小票前就校验——不能是符号链接、解析后必须在这个群的工作区目录下（和发件箱传群文件同一套口径），不合规直接拒，票都不记。
- **「现在想一个构想」同群只跑一个**：`make_idea_now` 和「现在备一批资讯」一样有同群互斥——这个群已经在想（不管是定时的还是手动点的），再点就回「已经在想了」，连点八次也只起一个。
- **「现在重新整理画像」同群只整理一次**：`refresh_profile` 走的就是平时画像刷新的同一个入口（profiles.refresh），同群互斥——这个群已经在整理了（定时的或手动点的），再点就回「已经在整理了」。它不往群里发任何东西，不用确认。
- **取消任务会真的停掉子 agent**：任务一被取消（网页取消、/mw 取消、管理员对话取消都一样），正在跑的子 agent 立刻停——不再调模型、不再交付、不再往群里发任何东西。统一从一个入口（`app.cancel_task_run`）停，各条取消路径都走它；停不到的后台协程还有一道兜底：协调器和子 agent 每一步开头都会再查一次任务状态，已是「已取消」立刻收手。
- **管理员工具单独一张注册表**：只给 `admin` 角色的工具和主模型 / 子 agent 的工具分开存，同名也各查各的（比如都有 `read_profile`），互相调不到；别的角色去调管理员工具会被工具层挡回。
- **一段对话同时只跑一轮**：上一句还在答时再发，网页返回「还在忙」，不会两轮插在一起。
- **跑不飞**：一条消息最多连续 12 轮模型调用；送进模型的只有最近 40 条消息；单条消息最长 20000 字、标题 100 字；工具结果进对话前截 6000 字。
- **错误遮密钥**：模型报错、工具结果、写回对话的每一行都先遮掉已知密钥（模型 / 搜索 / MCP 头）再落库，网页出响应前整份再遮一遍。
- **出问题不留白**：模型没配好、调用失败、轮数用完，都会在对话里写一条灰字提示，不会让网页一直转圈。

**永远不给的能力**（这些工具在代码里根本不存在）：

- 读、写密钥 / 端点 / 密码；改 MaiBot 的配置（`config/bot_config.toml` 也不碰）。
- 重启 MaiBot、重启服务器或任何服务；碰 `plugins/` 目录；装、删、改插件自己的代码文件。
- 给 MaiBot 的 planner 注册工具。

代码接口和网页接口见 `docs/07` §13。

### 构想怎么变成任务（2026-09-28）

构想页不再放「想要这个 / 做这个 / 不用了」按钮。每条构想可以点开看详情（要做什么、第一步、要多久、能不能做、给谁的），底部一个大按钮「复制要求」：复制出「帮我做这个构想：标题 / 内容 / 第一步 /（构想 #编号）」，到群里 @MaiBot 粘贴发送。收消息钩子认出「构想 #编号」且这条构想属于本群，就不问 Jev，直接按这条构想建待批请求（带 idea_id，来源写「群里 @ · 来自构想 #N」），构想标「等管理员批准」；免批的直接开工。已经在等批准 / 在做的只让 MaiBot 顺口说一句，不重复建。管理员拒绝后构想回到「新想法」，可以再提。管理员另有「···」菜单：直接开工（不用发到群里）、收起、有用 / 没用。
